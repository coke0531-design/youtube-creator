# 기획 브리프 · 연출 스토리보드 규격 (16:9 본편)

대본에서 슬라이드로 직행하지 않기 위한 **의도 계층 2종의 파일 규격**이다.

| 파일 | 위치 | 만드는 단계 | 무엇을 고정하나 |
|------|------|------|------|
| `BRIEF.md` | `01_대본/BRIEF.md` | Step 0.5 | 이 영상을 **어떻게 보여줄지**의 의도 (메시지·타깃·목표·앵글·톤·금지) |
| `STORYBOARD.md` | `04_영상소스/STORYBOARD.md` | Step 4 | 프레임별 **역할·설득 기법·감정 비트·샷 시퀀스**(나레이션 단어 큐) |

- 상류 계약: 대본은 이미 확정돼서 온다. 그래서 브리프는 "무엇을 말할까"가 아니라 **"어떻게 보여줄까"**만 다룬다.
- 하류 계약: STORYBOARD.md가 **편집지시서·타임라인.json의 상류**다 — 편집지시서의 연출 컬럼은 스토리보드에서 파생되며, 스토리보드에 없는 연출을 슬라이드에 넣지 않는다.
- 용어는 전부 `design.md` §4 모션 렉시콘·교리 4법칙·벡터 예약표를 따른다(자유 서술 금지).
- 결정 기록: `docs/개선안_2026-08-27_브리프-스토리보드-모션v2.md` §3-0·3-1·3-2.

## 1. BRIEF.md 규격 (Step 0.5)

**한 번 쓰면 그 작업의 진실(no-repeat token)이다** — 이후 어떤 단계도 브리프 질문을 다시 하지 않는다. 브리프와 어긋나는 판단이 필요해지면 브리프를 고치고, 고쳤다는 사실을 남긴다.

### 1-1. 프론트매터 (8키, 전부 필수 — `visual_concept`만 ②단계 후 확정)

```yaml
---
message: "이 영상이 전달할 단 하나의 결론 (한 문장)"
audience: "누구에게 / 그들이 이미 아는 것"
goal: "채널 목표 — 구독 · 신뢰 · 전환 중 무엇을 노리는가"
angle: "concept | how-to | listicle | story"   # 넷 중 하나
length: "14분 32초 (또는 예상 러닝타임)"
tone: "차분한 실무자 톤 / 과장·낚시 없음 등"
visual_concept: "선택된 비주얼 텔링 (아래 ②의 피치 중 채택안)"
must_show: ["반드시 화면에 나와야 하는 것", "..."]
avoid: ["절대 하지 않을 것", "..."]
---
```

- `angle`은 4종 enum이다. 애매하면 대본의 **첫 파트가 하는 일**로 고른다(문제 정의 = concept, 절차 = how-to, 열거 = listicle, 사건 = story).
- `must_show` / `avoid`는 리스트다. `avoid`에는 오너가 명시적으로 싫다고 한 것 + 이 워크스페이스의 금지(레드·다크 배경·전 구간 콜라주 등) 중 이번 편에서 유혹이 큰 항목만 적는다.

### 1-2. 본문 3절 (순서 고정)

```md
## 의도
(산문 3~6줄. 왜 이 영상이 이 사람에게 지금 필요한가, 시청자가 어느 상태로 들어와서
어느 상태로 나가는가. 프론트매터 값들을 잇는 이야기.)

## 재료
- 대본: 01_대본/script.md (파트 N개, 본문 M자)
- 녹음: 02_음성/... (트림본 기준 러닝타임)
- 사용자 제공 소스: 영상 소스/1.mp4 (…), 레퍼런스/…
- 리서치: content-oracle 산출물 경로 등

## 메모
(오너가 말한 것 / 추론한 것을 구분해 남긴다. 미확인 항목은 "미확인"으로.)
```

### 1-3. 채움 절차 (3단계)

1. **자동 추론** — `01_대본/기획메모.md` · `script.md` · content-oracle 리서치에서 8키를 먼저 채운다. 사용자에게 빈칸부터 묻지 않는다.
2. **비주얼 텔링 피치 3~5안** — 같은 대본을 **다르게 보여주는 방식**을 3~5개 제시한다. 규칙:
   - **최소 2안은 뻔하지 않은 경로**여야 한다(슬라이드+차트의 변주만 5개 = 실패).
   - 안마다: 한 줄 컨셉 / 화면에서 실제로 무엇이 보이나 / 어느 대목에서 가장 세게 먹히나 / 위험(제작비·톤 이탈).
   - **5안을 전부 제시한 뒤 추천 1안을 지목**한다. 처음부터 1안만 내놓지 않는다.
   - 채택안이 `visual_concept`이 된다.
3. **확인 게이트** — "오너가 말한 것"과 "AI가 추론한 것"을 **분리해** 제시하고 확인받는다. **오너 부재(자율 모드)면**: 추론 근거를 `## 메모`에 명시하고 그대로 진행한다(브리프 미확정을 이유로 파이프라인을 멈추지 않는다).

## 2. STORYBOARD.md 규격 (Step 4)

슬라이드 분해를 **머릿속이 아니라 파일로** 한다. 파일 = `## Video direction` 블록 1회 + `## Frame NN` 블록 × 프레임 수.

### 2-1. `## Video direction` 블록 (문서 상단, 편당 1회)

편 전체에 걸리는 결정만 여기에 둔다 — 프레임 블록에서 반복하지 않는다.

| 항목 | 내용 |
|------|------|
| 팔레트 | 4색 고정(흰 배경 `#ffffff` · 잉크 `#141413` · 앰버 `#F59E0B`/작은 텍스트 `#D97706` · 그린 `#16a34a`) |
| 모션 문법 | 기본 이징 `power3` 롱테일, 기본 등장 = 스태거--무게, 강조 preset 슬라이드당 1종 |
| 조류·예약 벡터 | 기본 조류 LEFT / 위쪽 = 파트 결론·고양 / Z 후퇴 = 파트 타이틀 도착 (design.md §4 벡터 예약표) |
| 전환 예산 | 이번 편에 쓸 전환 **유형 2~3종**을 여기서 지명(4종 이상 = 게이트 FAIL) |
| 정지 프레임 배분 | 클라이맥스 앞 쉼표를 어느 프레임에 둘지 목록 |
| 금지 목록 | 이번 편 한정 금지 (브리프 `avoid` + 무한 루프·프론트로딩 등 상시 금지) |

### 2-2. `## Frame NN` 필드 정의 (전부 필수)

| 필드 | 타입 | 정의 |
|------|------|------|
| `type` | **8역할 enum** | `hook` / `pain_point` / `product_intro` / `feature_showcase` / `benefit_highlight` / `social_proof` / `branding` / `cta` — 이 프레임이 영상 안에서 하는 일 |
| `persuasion` | 이름 붙은 기법 | 비유 · 대비 · 반복 강조 · 수치 증거 · 권위 인용 · 사례 · 반전 · 단계 분해 등. **막연한 "설명"·"소개" 금지** (이름이 없으면 기법이 아니다) |
| `beat` | `A→B` | 감정 비트. 시청자가 이 프레임 시작에 느끼는 것 → 끝에 느끼는 것 (예: `답답함→공감`) |
| `blueprint` | HF 블루프린트 id 또는 `compose` | 재사용 부품 이름(`grid-card-assemble`, `count-up`, `chart-story`, `state-chip-rail`, `before-after-wipe`, `marker-highlight`, `vox-annotate`, `per-word-rise`, `titlecard-lockup`, `cta-close` 등). 개작해 쓰면 `(Adapt)`, 처음부터 조립이면 `compose` |
| `route` | **지속 모션 루트 5종 중 1** | `staged-reveals` / `camera-with-intent` / `sequenced-ui-life` / `animated-sequences` / `carrier-led`. **구간 전체의 주인** — 누락 = 게이트 FAIL |
| `vec` | `{axis, dir}` | 이 프레임에서 **나가는** 전환 벡터. 기본 = 조류 LEFT(`{axis: x, dir: -1}`), 위쪽 `{axis: y, dir: -1}`, Z 후퇴 `{axis: z, dir: -1}` |
| `focal` | 한 구절 | 이 비트의 **주인공 요소** 하나. 포컬이 2개면 프레임을 쪼갠다 |
| `오디오` | `MM:SS.s~MM:SS.s` | `transcript.json` 실측 구간 (추정 금지) |

### 2-3. `Scene` 줄 문법 (샷 시퀀스)

```
Scene <N> (<시작>~<끝>s): "<나레이션 어절>" 어절에 <무엇이><렉시콘 preset으로> 등장
```

- 시각은 **전부 `transcript.json` 단어 타임스탬프에서** 나온다. 대본 글자수로 추정하지 않는다.
- **창 개수 = 나레이션 큐 개수.** 어절 큐가 3개면 Scene도 3개다.
- 시각은 프레임 시작 기준 **로컬 초**(0.0에서 시작). 구현의 `local = t - slide.start`와 같은 시간축이다.
- **프론트로딩 금지** — 첫 25%에 리빌을 다 쏟으면 FAIL. **후반 50%에도 리빌이 있어야 한다.**
- Scene 줄의 합은 프레임 오디오 구간을 **덮어야** 한다(빈 구간 = 정지 화면 회귀).
- 클라이맥스 앞 **0.3~0.75초 정지 홀드**는 Scene 줄에 명시한다(암묵 금지).
- Scene 줄이 **2개 이상이면 그 슬라이드는 `data-tl`**(샷 시퀀스, design.md §4)을 갖는다.
- **카메라 표기(2026-09-14, `route: camera-with-intent`)**: `… 어절에 카메라가 위 줄로 팬(새 초점, 0.9s) → 도착 후 상자 등장` / `… 관계 재정리로 넓게(fit, 1.0s)`. 이동 이유 3종(새 초점·상태 강조·관계 재정리) 중 하나를 괄호에 적고, 리빌은 '도착 후'에 둔다. 카메라만 있고 리빌이 없는 Scene은 리빌로 세지 않는다. 캔버스 슬라이드의 `focal`은 '관계 구조' 하나이고, 카메라 target 은 그 안의 현재 요소다. 화면 라벨 텍스트는 「」로 적는다(큰따옴표는 어절 큐로 대조된다).

### 2-4. 실전 예시 2프레임

```md
## Frame 07 — 두더지 잡기
- type: pain_point
- persuasion: 비유 + 반복 강조
- beat: 답답함→공감
- blueprint: grid-card-assemble (Adapt)
- route: staged-reveals
- vec: {axis: x, dir: -1}
- focal: 무한 반복 카드
- 오디오: 01:20.3~01:27.0

Scene 1 (0.0~1.2s): "하나 고치면" 어절에 카드1 등장(스태거--무게, 앵커)
Scene 2 (1.2~3.5s): "다른 데서 터지는" 어절에 카드2 + 마커 X 드로우온
Scene 3 (3.5~6.7s): "계속 반복" 어절에 반복 화살표 self-draw → 정지 홀드(클라이맥스 앞 0.4s 쉼표)
```

```md
## Frame 08 — 그래서 얼마가 줄었나
- type: benefit_highlight
- persuasion: 수치 증거 + 대비
- beat: 공감→기대
- blueprint: count-up
- route: sequenced-ui-life
- vec: {axis: y, dir: -1}     # 파트 결론 = 위쪽 (벡터 예약표)
- focal: 74% 빅 넘버
- 오디오: 01:27.0~01:39.4

Scene 1 (0.0~0.9s): "예전에는" 어절에 Before 뉴트럴 바 그로우 인
Scene 2 (2.1~4.0s): "지금은" 어절에 After 그린 바가 프로그레스 스윕(넛지 커브로 Before를 왼쪽으로 밀며 자리 확보 — 새 바는 버스트 중 등장)
Scene 3 (7.6~10.2s): "74퍼센트" 어절에 카운터 0→74 + 하이라이트 스윕 (후반 리빌 — 프론트로딩 방지)
Scene 4 (10.2~12.4s): 정지 홀드 0.5s 후 위쪽 벡터로 파트 결론 이탈
```

### 2-5. 게이트

작성 후 반드시 `python scripts/check_storyboard.py "결과물/<작업>/04_영상소스/STORYBOARD.md"` — `route` 누락, 샷 창이 오디오 구간을 안 덮음, 리빌 시각이 단어 타임스탬프 밖, 프론트로딩(첫 25%에 리빌 전부), 전환 유형 4종 이상을 결정론으로 막는다(`transcript.json` 대조).

## 3. 프레임 제작 분업 규약 (Step 5)

**감독(메인 세션)** = 판단. **프레임 워커** = 제작 노동.

### 3-1. 분업 여부

- **6프레임 이하 작업은 분업하지 않는다** — 인라인 제작이 더 빠르다(HF general-video 실측 규칙).
- 7프레임 이상이면 **워커 1명 = 2~3프레임**으로 병렬 디스패치한다.

### 3-2. 프레임 패킷 (워커에게 주는 전부)

패킷 = 아래 3개를 인라인으로 담은 프롬프트. **48KB 상한.**

1. **프레임 블록** — 해당 프레임의 `## Frame NN` 전문(필드 8개 + Scene 줄 전부)
2. **블루프린트 본문** — `blueprint`가 가리키는 부품의 마크업·모션 정의를 인라인으로
3. **인용 rule 본문** — 이 프레임에 걸리는 규칙(교리 4법칙 중 해당 조항, 쓰는 preset의 렉시콘 행, 4색·한글·자막 안전영역 21vh)의 **본문을 그대로 인라인**. 링크만 주지 않는다.

🔴 **워커는 STORYBOARD 전체를 열지 않는다** — 패킷이 전부다. 전체를 읽히면 워커가 편 전체 판단을 시작하고, 그게 후반부 품질 저하의 원인이다.

### 3-3. 워커 출력 계약

- 출력 = **`<section class="slide">` 조각 1개 + 그 슬라이드의 로컬 GSAP 타임라인 1개**. 그 외의 파일·전역 CSS·타임라인 수정 금지.
- 샷 시퀀스가 있으면 루트에 `data-tl`을 달고, 트윈은 `fromTo`만, 무한 `repeat` 금지(design.md §4).
- 자기 프레임의 오디오 구간 밖 시각을 쓰지 않는다(로컬 초 기준).

### 3-4. 감독의 일

1. 조각을 `presentation.html`에 **순서대로 조립**(전역 CSS·SLIDE_TIMELINE·캡처 블록은 감독만 건드린다).
2. 게이트 통과: `check_storyboard.py`(Step 4 직후) → `validate_pipeline.py` → `check_caption_safe.py` → 캡처 → `check_motion.py`.
3. 프레임 간 **벡터 연속성** 검수(연속 역방향 금지) — 워커는 옆 프레임을 모르므로 이건 감독 전담이다.

### 3-5. 모델 규칙

**판단(브리프·스토리보드·최종 검수)은 메인 세션**, **프레임 제작 노동은 위임(기본 opus)**. 워커의 "이상 없음" 보고를 최종 증거로 쓰지 않고 감독이 표본 감사한다.
