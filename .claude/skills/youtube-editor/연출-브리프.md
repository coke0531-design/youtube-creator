# 연출 브리프 템플릿 (DIRECTION.md)

> 정본 편입 2026-09-30, 출처 실험판 `youtube-creator-lab/연출브리프-템플릿.md` + G 본편 브리프(`DIRECTION.md`·`DIRECTION_실사시안.md`) 실례.
> 원 출처: Threads @ai_conlab 스레드가 모은 Opus 5.5 영상 10편의 공개 프롬프트에서 공통 구조를 뽑았다.
> twoclipping의 6블록(inputs/direction/structure/build/gotchas/start), nahiddotai의 "분야+캐릭터+숫자 제약+30초 상한",
> riso-windowseat의 "seek(t) 결정론 + 가장 어려운 프레임 먼저 + 프레임 시트 검수"를 설명 영상용으로 옮겼다.
>
> 쓰는 곳: `결과물/<작업>/04_영상소스/DIRECTION.md`(SKILL.md Step 4). 메인 세션이 한 장으로 쓴다.
> 각 블록은 비워 두지 않는다. 모르는 값은 "미정"이 아니라 결정해서 적는다. 빈 블록이 있으면 Step 5(킷)로 가지 않는다.
> 규칙 원문: 빌드 계약 = SKILL.md §4, 크기·카메라 = §4-3, 실사 = §4-4, 금지 = §5, 스타일 = `스타일팩.md`, 장치 = `장치사전.md`, 킷 함수 = `킷-규격.md`.

```
<입력>
- 나레이션: 02_음성/narration.m4a, <길이>초, 비트 <N>개 (03_자막/beats.json — scripts/film/segment.py --beats-only)
- 자막: 03_자막/full.srt (교정·16자), 대본: 01_대본/script.md (## 본문)
- 대본에서 장치가 붙어야 할 자리:
  - 숫자: (예) "2분 → 35분" (비트 #12)
  - 비교: (예) 일반 모드 vs 울트라 모드 (비트 #5~7)
  - 절차: (예) 플랜 모드 → 울트라 모드 순서 (비트 #3~4)
  - 실패담/경고: (예) 방향 틀린 채 오래 일함 (비트 #9)
  - 지침: (예) 작은 과제부터 (비트 #20)
- 화면에 보여줄 실물 이름: (예) /effort 명령, 설정 메뉴 이름 — 대본에 있는 라벨만 그대로 허용. 실제 앱의 색·아이콘·레이아웃 흉내 금지
- 실물 소스 표 (영상 소스/ 가 있을 때. 없으면 "없음"이라고 적는다):

| 파일(영상 소스/) | 규격 | 내용(컨택트 시트로 확인) | 대사 구간(비트 #, 원본 초) | 카드 안 / 창 | 재생 속도 rate |
|---|---|---|---|---|---|
| (예) 소스 123 합본.mp4 컷 A 0~12.05 | 1920×1080 30fps 31.07s, 소리 안 씀 | 클로드 앱 상단 Code → 노력 Ultracode | #28~#30 117.5~129.2 | 카드 안 고정 창 WIN | 362/352.5 = 1.027 |
| (예) 울트라 좌우 합본.mp4 왼쪽 1920 | 3840×1080 30fps 5.97s | 클로드 코드 /effort | #1 0.30~5.08 | 무대 위 흰 카드 창(inCard) | 179/143.4 = 1.248 |

  - rate = 클립 프레임 수 ÷ (대사 구간 초 × 30). 허용 0.6~1.5. 밖이면 한계 속도로 틀고 남는 시간은 마지막 프레임 유지. 보간 금지.
  - 프레임 추출 경로: 04_영상소스/실사프레임/<이름>/%04d.jpg (30fps). 추출 뒤 실제 장수를 세어 표에 적는다.
- 오프닝 콜라주: 없음(기본) / 있음(이유). 첫 프레임 = 썸네일 원칙.
</입력>

<방향>
- 분야: AI 노하우 설명 영상 (유튜브 본편 16:9, 한국어 시청자)
- 스타일: P1 종이 무대 기본 + 카드 안 P2(스타일팩.md 혼합 규칙). P2 구간 목록: <비트 #~#: 무엇을 카드 안에서> … (영상당 2~6회, 각 10~60초)
- 팔레트: 종이 #F7F3EA, 잉크 #141413, 앰버 #F59E0B(작은 글자 #D97706), 그린 #16a34a, 흰 카드 #FFFFFF (design.md §4-A). 전면 색 패널 <없음 / 비트 #, 러닝타임 10% 이하>
- 글꼴: Pretendard 1종, 굵기 3단(500/700/800). 라벨 ≥ 36px, 명령·메뉴 라벨 ≥ 44px, 숫자 ≥ 130px
- 질감: 종이 그레인 6~8%(카드 밖만). 선은 곧게, 끝만 둥글게
- 주인공(객체 연속성, 전 막 공통 — 템플릿/film/kit.js 그대로): ① 캐릭터(별표 8비트, h 300 기본·≥270, 표정 base/focus/surprise 3종) ② 토큰(카드 안, 지름 ≥200) ③ <작업 카드·HUD 칩 문구·우상단 배지 등 이 영상의 고정 요소>
- 카메라: P1 고정 + 비트 경계 컷·큰 이동. P1→P2 = enterCard 0.5초, P2→P1 = leaveCard 0.5초. 카메라 규칙 4조(SKILL.md §4-3)
- 화면당 글자 상한: <숫자>자 (키워드·숫자·대비만. 나레이션 복창 금지. 메뉴·명령 라벨 예외)
- 최소 크기: 캐릭터 ≥ 270px, 토큰 ≥ 200px, 핵심 숫자 ≥ 130px, 장치 본체 ≥ 화면 폭 30%. 움직임은 0.5초에 58px 이상 이동 또는 면적 20% 변화
</방향>

<구조>
- 총 <길이>초, 비트 <N>개, 평균 장면 길이 목표 <2~4>초
- 막 표 (막 1개 = 필름 1개 film_<막>.html, 막 담당 1명, 5명 이하):

| 막 | 구간(원본 초) | 길이 | 내용 | 팩 |

| <A1> | 0.0~<a> | | | P1 / P2(비트 #~#) |

- 핸드오프 표 (막 N 마지막 프레임 = 막 N+1 첫 프레임 = kit_ext.js 의 KIT.HANDOFF.<경계>(ctx)):

| 핸드오프 | 시각 | 화면 상태 |
|---|---|---|
| <A1A2> | <a> | <캐릭터 위치·카드·HUD 칩·배지 상태> |

- 막별 뼈대: 막 담당이 BEATS_<막>.md 로 세분할 흐름 한 단락씩
- 수미상관: 첫 비트의 <요소>가 마지막 비트에 <어떻게> 돌아온다
- 장치(장치사전.md에서 3~5개 이상): #<비트> <장치 이름>: <이 영상에서 어떻게> …
```
