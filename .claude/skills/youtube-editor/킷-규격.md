## 0. 규칙 요약

- **좌표계**: 캔버스 1920×1080 픽셀. 도형 함수의 `x,y`는 **중심**. 예외: `character`·`troop`·`person`·`crowd`는 **발 밑 중앙**(보통 `y = KIT.GROUND = 800`), `rr`·`bar`·`checklist`·`listMenu`는 왼쪽 위(또는 왼쪽 끝), `line`·`arrow`·`strike`는 점 좌표.
- **하단 200px 금지**: 무대에서도, 카드 안(카드 로컬 좌표)에서도 y > 880(`KIT.SAFE`)에 아무것도 그리지 않는다. 카드 줌 p=1에서는 흰 카드 바탕만 하단까지 깔린다(자막 뒤 바탕, 정상).
- **상태 없음**: 모든 함수는 인자만으로 그린다. t를 넣어 값을 계산해 인자로 넘긴다. `Math.random`·타이머·rAF·CSS transition·`<video>` 금지.
- **그리기 함수는 `setTransform`을 부르지 않는다**(카메라·카드 줌 안에서 그대로 쓰려고). 예외는 `BASE`·`cardFull`·`screen`·`camApply`와 `enterCard/leaveCard`(프레임 전체를 그림). 무대 콜백·카드 안 콜백 안에서는 `BASE`를 부르지 말고 `ctx.save/translate/restore`만 쓴다.
- **팔레트(P1 하나)**: `KIT.C = {paper:'#F7F3EA', ink:'#141413', amber:'#F59E0B', amberD:'#D97706', green:'#16a34a', white:'#FFFFFF'}`. 회색은 `KIT.G(a)`(잉크의 투명도)만. 앰버 작은 글자는 `amberD`. 전면 색 패널 없음. 그레인 6%는 `BASE`가 깔고, 카드가 그 위를 덮어 카드 밖에만 보인다. 킷 안의 보조 hex(`#DCD8CF` 꺼진 토큰, `#E9E6E0` 회색 문서)와 live.js의 `#FF00FF`(못 불러온 실사 프레임 표시) 밖의 hex는 필름에 쓰지 않는다.
- **글꼴**: Pretendard 1종(500·700·800), 로컬 `C:/Windows/Fonts`, 실패 시 Malgun Gothic. `KIT.F(weight,size)`. 900을 주면 800으로 내린다(굵기 3단).
- **최소 크기**: 캐릭터 h ≥ 270(`character`가 강제, 기본 300), 토큰 r ≥ 100(강제, `mini:true`만 예외), 큰 숫자 ≥ 130(강제), 라벨 ≥ 36, 명령·메뉴 라벨 ≥ 44(`chip`·`appScreen`·`listMenu`·`inputBox` 기본값), 카드 폭 ≥ 1150(`KIT.CARD` = 1400).
- **선은 곧게, 끝만 둥글게**(`line`). 손그림 흔들림 금지.

## 2. 막 필름 템플릿

`템플릿/film/film_act_template.html`을 `04_영상소스/film_<막>.html`로 복사해 시작한다(30초 샘플: 첫 프레임 THUMB → P1 걷기·큰 숫자·카메라 줌 1회 → enterCard → 실사 고정 창 + 창 안 줌 + 토큰 me 상주 → 창 축소 + 결과 문서 → leaveCard → 수렴 → 엔드카드). 뼈대:

```html
<script src="kit.js"></script><script src="live.js"></script><!-- kit_ext.js 가 있으면 kit.js 다음 -->
<script>
window.FILM={duration:63.9,width:1920,height:1080,fps:30,offset:117.5,
  holds:[[3.4,5.4,"#29 메뉴 라벨 '코드'"]]};                // t·holds = 막 기준(0부터)
const CAM_STAGE=[[0,960,440,1],[4.0,960,440,1],[5.0,760,420,1.2],[11.2,760,420,1.2],[12.2,960,440,1]]; // 숫자로 풀어 적는다(cam_check)
function draw(t){
  if(t<=0){K.HANDOFF_X.AB(ctx);return;}                    // 첫 프레임 = 이전 막 핸드오프(1막은 THUMB)
  if(t>=TLAST-1e-6){K.HANDOFF_X.BC(ctx);return;}           // 마지막 프레임 = 다음 막 핸드오프(마지막 막은 THUMB 엔드카드)
  // … 막 연출 …
  K.screen(ctx); K.chrome(ctx,{hud:'① 사용법',badge:{checked:[0,0,0]}});   // 항상 마지막, 전환 밖
}
window.seek=async function(t){ t=K.clamp(t,0,D); await LIVE.render(liveNeed(t),()=>draw(t)); };  // 실사 없으면 동기 draw(t)
KIT.ready().then(async()=>{ /* 첫 실사 프레임 선로드 */ await window.seek(0); window.FILM_READY=true; });
</script>
```

- 원본 초 − `FILM.offset` = 막 기준 초. 숫자를 그리는 줄 옆에 `// 출처: 비트 #n`(전체 번호).
- 무대 장면 한 프레임: `K.BASE(ctx); K.camApply(ctx,cam); …무대…; K.screen(ctx); K.chrome(ctx,…)`. 카메라를 썼으면 경계·enterCard 0.5초 전에 `{cx:960,cy:440,z:1}`로 돌아온다.
- **카메라 규칙 4조**(`scripts/film/cam_check.py`): 이동 뒤 ≥ 3초 유지 · 한 이동 |Δz| ≥ 0.15 또는 팬 ≥ 288px · 6초 안 왕복 금지(되돌아오기 시작은 앞 이동 끝에서 6초 **넘게** 뒤) · 구간 ÷ 이동 ≥ 4초. 카메라 배열 이름은 `CAM…`으로 시작, 값은 숫자 리터럴.

## 3. 핸드오프(이음매) 호출법

- 막 N 마지막 프레임과 막 N+1 첫 프레임은 **핸드오프 함수만** 부른다(덧그리기 금지).
- **수렴**: 마지막 0.5초 동안 `SPEC.<경계>` 값으로 lerp. 무대 그림은 `STAGE.<경계>`와 같은 함수·같은 인자가 되도록(예: 캐릭터 x를 `lerp(x0, SPEC.BC.hero.x, e)`). HUD는 경계 0.3초 전 `hudSwap`.
- 다음 막 첫 0.3초는 그 상태에서 출발(정지 또는 아주 작은 첫 동작).
- 카드로 끝나는 경계: 앞 막은 끝에서 흰 카드를 `inCard(ctx, CARD, null)`로 올려 두고 끝난다. 다음 막 첫 프레임 `enterCard(ctx,0,CARD,…,STAGE)`는 핸드오프와 픽셀이 같다(G 측정 max 0).
- 첫 프레임 = 썸네일 원칙: 1막 t<0.3은 `THUMB`(썸네일 구도), 마지막 막 마지막 프레임도 `THUMB`(수미상관).

G 편 예시 좌표(`HANDOFF_SPEC`): THUMB = 캐릭터 (960, h340) + 군단 실루엣 6(y760, h240) + 도장 (960,250) 120px · G1G2 = 캐릭터 (190) + 군단 6 + 단계 6칸 레일 · G2G3 = 캐릭터 (200) + 빈 `CARD` · G3G4 = 캐릭터 (560) + 앱 카드 3장 `APP3`(600×338) · G4G5 = 캐릭터 (760) + 서류 카드 + 체크 도장.

## 4. enterCard / leaveCard 호출 패턴

동작: 카메라가 무대 전체 창에서 카드의 16:9 내용 창으로 줄어든다(폭 지수 보간 = 일정한 확대 속도, easeInOut). 카드 모서리·그림자는 p에 따라 사라지고 무대는 화면 밖으로 밀려난다. 카드 안은 `drawInside`가 **카드 로컬 1920×1080 좌표**로 그리며, enter는 투명도 p 0→0.45에서 0→1, 스케일 0.94→1. 측정(G): enter p=1 = `cardFull` 차 0, enter p=0 = 무대 + 빈 카드 차 0, leave p=0 = `cardFull` 0, leave p=1 = 무대 + `inCard` 0.

```js
const R=K.CARD;
const stage=(ctx)=>{ K.groundLine(ctx); K.character(ctx,{x:200,y:K.GROUND,h:300,face:'focus'}); };  // 월드 좌표, BASE·setTransform 금지
const inside=(ctx,t)=>{ /* 카드 로컬 1920x1080. y>880 금지, 좌상단(HUD)·우상단(배지) y<110 비우기 */ };
if(t<0.5)      K.enterCard(ctx, K.pr(t,0,0.5), R, c=>inside(c,t), stage);
else if(t<43)  K.cardFull(ctx, c=>inside(c,t));
else if(t<43.5)K.leaveCard(ctx, K.pr(t,43,43.5), R, c=>inside(c,t), stage);
else { K.BASE(ctx); stage(ctx); K.inCard(ctx, R, c=>inside(c,t)); }
K.chrome(ctx,{hud:'① 사용법',badge:{checked:[0,0,0]}});
```

- 카드 안 줌·팬은 `inside` 안에서 `save/translate/scale/restore`. **enter/leave 0.5초 동안은 카드 안 카메라를 항등으로**.
- 이미 내용이 있던 카드로 들어가면 `enterCard(…,{fade:false})`, 빈 카드로 나오려면 `leaveCard(…,{fade:true})`.
- 다른 rect로 줌하려면 `R`만 바꾼다(폭 ≥ 1150). 컷으로 팩을 바꾸지 않는다: P1↔P2 사이에는 반드시 enter/leave 0.5초.

## 5. 캐릭터 규격(모든 편 공통 — 오너 일관성 요구)

주인공은 **한 명, 한 모양**이다. 편마다 다시 그리지 않고 `KIT.character`만 부른다.

**몸 = 별표 도트 13×13**(`KIT.STAR`, 클로드 별표를 몸으로) + 아래 다리 2칸 = 세로 15칸. 칸 크기 `ps = h/15`. 발 밑 중앙이 (x,y).

```
......X......
..X...X...X..
...X..X..X...
....XXXXX....
.X.XXXXXXX.X.
..XXXXXXXXX..
XXXXXXXXXXXXX      ← 6행: 가로 전체(팔 reach·hold가 이 줄에 붙는다)
..XXXXXXXXX..
.X.XXXXXXX.X.
....XXXXX....
...X..X..X...
..X...X...X..
......X......
    (다리: 5열·7열, 13~14행, 잉크)
```

- **색**: 몸 앰버 `#F59E0B`, 눈·다리 잉크 `#141413`. 입 없음. 테두리 없음.
- **표정 3종만**(눈 모양으로만 구분, G판):
  - `base` 기본 — 세로 막대 눈 2개(1×2칸, 4열·8열, 5~6행)
  - `focus` 집중 — 가로 막대 눈 2개(2×1칸, 6행): 확신·작업 중
  - `surprise` 놀람 — 큰 네모 눈 2개(2×2칸, 4.5~6.5행): 발견·충격
- **자세 6종**: `stand`(서기) · `walk`(걷기, `walk:t` → 다리가 한 칸씩 엇갈림, 이동 중이면 반드시) · `tilt`(갸우뚱 −0.13rad, 의문) · `reach`(오른팔 뻗기, `reach` 0~1, 가리키기) · `cheer`(두 팔 위, 성공) · `hold`(앞팔 + 손, 카드·서류를 든 자세). `flip:true` = 왼쪽 보기.
- **변형 2종**: `silhouette:true` = 잉크 16% 실루엣(눈 없음, 군단 뒷배경·썸네일 뒷줄) · `tint:'gray'` = 잉크 38% 몸(눈 있음, 휩쓸리던 나·꺼진 나).
- **크기**: 주인공 h 기본 300, **≥ 270 강제**(작게 쓰면 자동으로 270). 썸네일·엔드카드만 340. 군단원(`troop`)은 기본 220, 최소 160.
- **땅선 GROUND = 800**. 캐릭터 y는 땅선(점프 중에도 발 기준은 y, 높이는 `jump`). 무대 여러 줄이 필요하면 y를 바꾸되 땅선도 함께 그린다.
- **점프 = `KIT.hop(t,t0,.45,60)`**(높이 60, 0.45초 사인 한 번). 강조는 50~60, 110 같은 큰 점프 금지.
- **토큰 관계**: 카드 밖 = 캐릭터, 카드 안 = 토큰. `token({kind:'me'})` = 흰 원 + 앰버 별표(별 칸 = r·1.34/13) + 같은 눈 3종, 테두리 앰버. `'ai'` = 잉크 원 + 앰버 별표 + 눈(에이전트), `'gray'` = 꺼짐(`#DCD8CF` 원 + 회색 별, 눈 없음). 같은 인물을 동시에 두 곳에 그리지 않는다. 카드 안 구간이 15초를 넘으면 토큰 me를 구석(카드 로컬 (150,740) r100)에 상주시킨다.
- **군단 규칙**: 카드 밖 `troop`(같은 캐릭터 복제, 기본 6명), 카드 안 `token({kind:'ai'})` 6개. 주인공 아닌 사람들(시장·청중·경쟁자)은 `person`/`crowd`(별표 아님)로 그려 주인공과 섞이지 않게 한다.
- **금지**: 표정 추가(입·눈썹·땀·하트 눈 등) · 색 변경(몸 앰버 외, gray tint·실루엣 외) · 다른 마스코트·새 캐릭터·로고 창작 · 필름 안 `character`/`STAR` 재정의 · 손그림 흔들림 윤곽.

## 6. 실사 창(편입안 §3, G r2 확정)

1. 실사는 항상 **카드 안 세상**: 카드 안(P2 `cardFull`) 고정 창 `WIN {x:1040, y:510, w:1316, h:740, r:32}`(카드 로컬 y 140~880, HUD 칩 아래 여백 ≥ 50px, 왼쪽 끝 382 > 토큰 250) 또는 무대 위 흰 카드 창(`inCard`, r 32). 둥근 모서리 + 잉크 테두리 4px. 각진 사각 금지.
2. 카메라 줌·팬은 **창을 움직이지 않고 창 안의 그림에만**(창 클립, 템플릿 `picDraw`). 그림이 창을 늘 덮도록 기준점을 `WIN ± w/2·(1−1/z)`로 제한. 카메라 규칙 4조 그대로(`CAM_CARD` 배열).
3. 대사 구간 = 실사가 보이는 구간. 클립 길이는 **재생 속도**로 맞춘다: `rate = 클립 프레임 수 / (대사 길이 × 30)`, 0.6~1.5 허용, 보간 금지. 범위 밖이면 한계 속도 + 남는 시간 마지막 프레임 유지. 프레임 번호 = `min(N−1, floor((t − t0) × 30 × rate))`. (템플릿: 30장을 3초 대사에 → 0.33 → 0.6 제한 → 1.67초 재생 + 1.33초 마지막 프레임.)
4. 결정론: `<video>` 금지. `ffmpeg -i 소스.mp4 -vf fps=30 -q:v 3 04_영상소스/실사프레임/<이름>/%04d.jpg`(1부터) + `live.js`. 필름에서 `LIVE.N.<이름> = 프레임 수`를 등록하고(live.js의 기본 표는 G 편 세트), `seek`는 `await LIVE.render(need, ()=>draw(t))`, `FILM_READY` 전에 첫·끝 프레임 선로드. 캐시 LRU 60장. `capture.py --verify-seek` 필수(못 불러온 프레임은 `#FF00FF`로 그려져 검사가 잡는다).
5. 실사 위에 가짜 UI 덧그리기·앱 모양 흉내 요소 금지. 라벨·칩·결과 문서는 창 밖(카드 안 빈자리)에. 녹화는 확대·흐림 전환 없이 받는 것을 권장(필름 줌과 겹침).
6. DIRECTION `<입력>` 실물 소스 표: 파일 · 규격 · 내용 · 대사 구간(비트 #) · 카드 안/창 · rate.

## 9. 금지

- kit에 없는 주인공 창작(새 캐릭터·새 마스코트·새 로고). 보조 도형은 `paperCard`·`whiteCard`·`bar`·`line`으로, 편 전용 소품은 kit_ext.js로.
- 컷으로 팩 바꾸기(P1↔P2는 enter/leaveCard만). 전면 색 패널. P3.
- kit.js 수정(버그는 필름 안에서 우회하고 작업정보에 기록 → 메인에게 보고 → 정본 킷 개정은 VERSION·골든·변경 기록과 함께).
- 실제 앱의 색·아이콘·배치 흉내(`appScreen` 추상 화면 또는 실사 창만, 라벨은 대본 실물 이름만). 사각지대 프롬프트 문장 창작(앰버 빈 줄 + 라벨). 표정 3종 초과. 손그림 흔들림 선.
- 나레이션 복창(예외: 명령·메뉴 라벨).

## 10. 알려진 한계

- `miniChecklist`는 작아서 체크 순간이 "움직임"으로 안 잡힌다. 체크 비트에 무대의 큰 요소를 같이 움직일 것.
- `APP_INSIDE` 3장은 600×338 크기에서 글자가 약 10px로 줄어 읽히지 않는다(무늬 역할). 읽혀야 하는 순간은 카드 안(P2)에서.
- `appScreen`을 카드 로컬 기본 자리(y 100~840)에 두면 좌상단 HUD·우상단 배지와 닿지 않는다. 더 위로 올리면 겹친다.
- `inputBox`의 `tail`은 글자 폭을 그만큼 줄여 배치한다(44px 아래로는 줄이지 않고 두 줄로 접는다).
- `live.js`의 `LIVE.N` 기본 표는 G 편 세트(s123·cc·gpt)다. 새 세트는 필름에서 등록한다(live.js 수정 금지).
