# 인포그래픽 퍼스트 디자인 가이드 (16:9 슬라이드)

영상 소스 슬라이드를 위한 **인포그래픽 퍼스트** 디자인 가이드.

> 색/폰트/모션 토큰의 단일 출처는 프로젝트 루트 [design.md](../../../design.md)다. 이 문서와 충돌하면 design.md가 우선. 배경은 **흰색 고정**, 팔레트는 **4색**(잉크/앰버/그린 + 흰 배경)이다.

---

## 디자인 철학

1. **말로 풀지 말고 그려서 보여준다** — 설명이 필요한 내용일수록 시각화가 먼저다
2. **한 슬라이드, 한 인포그래픽** — 하나의 시각적 메시지에 집중
3. **데이터를 시각화하라** — 숫자/비교/프로세스는 반드시 차트/다이어그램/바로
4. **움직임이 이해를 돕는다** — 순차 스태거 빌드업으로 정보 전달
5. **텍스트의 역할은 라벨·값 표시까지** — 주인공은 항상 그림이다
6. **여백이 시각물을 살린다** — 화면의 50%+ 여백 유지

### 금지 패턴

```
❌ 텍스트만으로 슬라이드 구성 (인포그래픽으로 대체 가능한 경우 — 사실상 항상 가능)
❌ 검정/다크 배경 (영상 소스는 흰색 고정)
❌ 4색 외 색 (보라/파랑/네온그린/골드/레드)
❌ 보라색 그라데이션, 무지개 그라데이션
❌ 게이지/스피드미터(반원형 진행률) — 대시보드 느낌. 도넛/바로 대체
❌ 이모지를 떠다니게 하는 장식(플로팅·파티클)
❌ 그리드 레이아웃으로 정보 나열만
❌ 얇은 보더 박스 나열
❌ 큰 텍스트만 띡 — 시각화 없이 대형 타이포만 쓰는 건 최후의 수단
```

## 인포그래픽 결정 트리 (슬라이드 설계 시 필수)

```
나레이션 내용 분석
├─ 숫자/데이터가 있나? ──────→ 빅 카운터(data-counter) + KPI 카드
├─ 비교가 핵심인가? ────────→ 가로 바(hbar) / 분할 카드(split-row)
├─ 비율/퍼센트인가? ────────→ 도넛 차트 + 중앙 숫자
├─ 달성률/점수/완성도? ──────→ 도넛 차트 또는 가로 바
├─ 단계/프로세스인가? ──────→ 번호 카드(num-list) 순차 빌드업
├─ 시간 흐름/역사인가? ──────→ 타임라인 (가로 점+선)
├─ 관계/연결을 보여주나? ────→ SVG 노드맵 / Mermaid(CDN)
├─ 도구/기술 소개인가? ──────→ 브랜드 로고 칩 + 라벨
├─ Before/After인가? ──────→ ba-container (Before=뉴트럴 ×, After=그린 ✓)
├─ 핵심 수치 나열인가? ──────→ KPI 카드 쌓기
├─ 인용/발언인가? ──────────→ quote-block (+ 원형 인물 사진, 앰버 보더)
├─ 한 슬라이드 안 단계 연출? → 스테이지 시스템 (.stage 순차 전환)
├─ 감정 전환/리액션/질문? ───→ 스티커 (레퍼런스/스티커/ 먼저 스캔 — 없으면 제작 후 등재) 또는 SVG 아이콘 (460px+) + 미니멀 라벨
├─ 스토리/비유/개념 설명(수치 없음)? → 큰 SVG 장면 그림 (⏸ 화이트보드 드로잉은 비활성 — SKILL Step 6.6)
└─ 위 모두 해당 없음? ──────→ SVG 기본 도형 (원/삼각형/화살표/느낌표) + 라벨
```

**원칙**: 텍스트만으로 슬라이드를 채우는 건 마지막 수단이 아니라 **금지**다. 항상 "이걸 그림으로 보여줄 수 없을까?" 먼저 생각.

### 인포그래픽 적용 점수 (슬라이드마다 체크)

- 시각 요소(차트/도형/아이콘/카드)가 화면 40%+ 차지 → +4점
- 시각 요소가 있긴 한데 작음 (40% 미만) → +2점
- 애니메이션이 데이터를 "그리는가"? (바 성장, 도넛 드로잉, 카운터) → +2점
- 시각 요소가 300px 이상인가? → +1점
- 텍스트가 라벨 역할만 하는가? → +1점
- 대형 타이포가 화면 중앙 주인공 → -5점
- 텍스트만으로 구성 → -10점 (자동 FAIL)

**최소 통과 점수: 4점. 2점 이하는 반드시 리팩터.**

### 🔴 한글 줄바꿈 규칙 (2026-07-02)

보일러플레이트가 구조적으로 처리한다 — **임의로 제거하지 않는다**:

- `body { word-break: keep-all; overflow-wrap: break-word; }` — 어절 중간에서 꺾이지 않고, 컨테이너를 넘칠 때만 강제 개행

AI가 할 일:

- 조사·단위가 붙는 짧은 구("3만 원", "GPT-5로")가 갈라지면 `<span class="nobr">`로 감싼다 — **짧은 구절만** (긴 구절은 넘침 위험)
- 히어로/타이틀처럼 줄바꿈 위치가 메시지를 좌우하는 문구는 의미 단위로 `<br>`을 직접 넣는 것이 가장 확실하다
- 완성 후 각 슬라이드를 훑어 어색한 줄바꿈(어절 쪼개짐, 한 단어 낙오)이 없는지 확인한다

## 레이아웃 규칙

- **중앙 정렬** — 시각물이 화면 중앙. 좌측 아이콘 + 우측 목록 같은 쏠림 금지
- **시선이 꽂히는 지점은 하나** — 슬라이드당 차트 하나, 다이어그램 하나
- **라벨은 위에** — 인포그래픽 위에 섹션 라벨 칩
- **목록은 칩/카드로** — 불릿 텍스트 나열 금지, flex-wrap 칩 또는 번호 카드
- **하단 230px 비우기** — 자막 안전 영역 (보일러플레이트 패딩이 처리 — 임의 제거 금지)
- **단계 연출은 스테이지로** — 같은 주제의 빌드업은 `.stage` 전환, 새 슬라이드 남발 금지

### 레이아웃 안정성 (시프트 금지)

```
✅ 안전: opacity/transform만 변화 (.el 스태거, 차트 드로잉)
✅ 안전: 스테이지 전환 (absolute 레이어 교체)
❌ 금지: 등장 애니메이션이 다른 요소를 밀어내는 것
❌ 금지: translateY 40px 초과 이동, scale 0.88~1.08 범위 초과 (예외: 캔버스 카메라의 `.canvas` 레이어 x·y·scale 트윈과 `.zoomwrap` 1.3배 — design.md §4 '캔버스 카메라' 행, 2026-09-14)

**레이아웃 실측 규칙 (2026-09-14 저녁, 게이트 = `scripts/check_layout.py`)** — 절대 좌표 장면(`.scene`·캔버스)은 눈이 아니라 실측으로 잡는다:
- 겹침 0: 도형끼리 사각형 교차 금지, 선은 도형 안쪽(선 굵기·6px)을 관통하지 않는다(선 끝은 도형 **앞**에서 멈춘다 — 화살은 상자 앞, 모래시계는 점선 **위**). 의도한 포개기(종이 더미·말풍선 묶음)는 같은 `data-grp`, 경로 위 정거장(카드·체크포인트)은 선에 `data-under="kcard abs"`.
- 잘림 0: 카메라 프레임·뷰포트 가장자리에 일부만 걸치는 요소 없음(선 포함). 프레임은 구역 단위, 구역은 세로로 떼어 놓는다.
- 과밀: 한 프레임에 보이는 도형 ≤ 8단위(`data-grp` 같으면 1단위, 선은 세지 않음). 넘치면 화면을 나누거나 앞 단계를 dim(0.22)으로 물린다.
- 정렬: 라벨 칩은 도형 **아래** 가로 중심(`data-cx`로 중심 x 선언 — 폰트 로드 뒤 폭을 재서 left 계산), 같은 줄 요소는 `data-row`, 같은 열은 `data-col` 선언 → 중심 편차 ≤ 6px. 같은 종류·같은 크기 도형은 한 줄 또는 한 열.
```

## 모션 규칙 (SSOT: design.md §4 **모션 렉시콘**)

모션의 용어·구현 클래스·시간의 단일 출처는 design.md §4 렉시콘 표다. 지시·편집지시서·구현 모두 그 용어를 쓴다. 자주 쓰는 매핑 요약:

| 렉시콘 용어 | 구현 | 용도 |
|------|------|------|
| 스태거 / 라이즈 / 팝 | `.el` (+`--rise`/`--pop`) + `--i` | 기본 등장 (팝 = 로고·아이콘·스티커) |
| 그로우 스케일 / 펄스 | `.grow-scale` / `.pulse` | 임팩트 등장 / 시선 유도 |
| 그로우 인 | `.hbar-fill` / `.donut-arc` | 데이터가 0→값으로 "그려진다" |
| 카운터 | `data-counter` | 숫자 카운팅 (`data-from`으로 A→B) |
| 프로그레스 스윕 | `.hbar-fill--sweep` / `.donut-arc--sweep` | 이미 그려진 값이 A→B로 차오름 |
| 하이라이트 스윕 | `.hl-sweep` | 핵심 문구 형광펜 강조 |
| 드로우온 | `.u-draw` / `.strike-draw` / `.draw-on`(SVG, `pathLength="1"`) | 밑줄·취소선·선 긋기 |
| 와이프 리빌 | `.wipe-reveal` | 마스크 통과 극적 등장 |

**원칙**: 순차 등장(스태거), 동시 등장 금지. ease-out. 슬라이드 전환은 크로스 디졸브 0.45s(기본값 — 별도 지시 불필요). **스윕·드로우온·리빌류 강조 preset은 한 슬라이드에 1종만.** 키네틱 타이포그래피는 히어로/훅 한정, 영상당 1~2회 (렉시콘 게이트).

## Mermaid 다이어그램 (구조/관계용)

복잡한 관계도가 필요하면 mermaid CDN을 사용한다 (보일러플레이트에 추가):

```html
<script type="module">
  import mermaid from 'https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs';
  mermaid.initialize({ startOnLoad: true, theme: 'neutral' });
</script>
<pre class="mermaid">
graph LR
  A[아이디어] --> B[프롬프트] --> C[결과물]
  style C fill:#F59E0B,stroke:#D97706,color:#141413
</pre>
```

노드 스타일: 강조 `fill:#F59E0B,stroke:#D97706,color:#141413` / 성공 `fill:#16a34a,color:#ffffff` / 기본 `fill:#f7f6f4,stroke:#141413,color:#141413`.
