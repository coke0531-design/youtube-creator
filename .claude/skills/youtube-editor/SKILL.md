# YouTube 영상 소스 제작 (16:9)

대본·나레이션 음성 → CapCut 검수에 바로 쓰는 **4종 산출물**을 만든다:

| # | 산출물 | 파일 | 설명 |
|---|--------|------|------|
| ① | 영상 소스 | `04_영상소스/presentation.html` | 슬라이드형 HTML — **SLIDE_TIMELINE 내장 + 캡처 모드(?capture=1)** (자막 데이터와 싱크 일치) |
| ② | 자막 | `03_자막/full.srt` | Whisper 전사 → 보정한 SRT (+ transcript.json 원본 보존) |
| ③ | 동기화 데이터 | `편집지시서.md` + `타임라인.json` | 슬라이드 ↔ 오디오 타임코드 매핑 (사람용 MD + 기계용 JSON — 캡처·드래프트 조립의 입력) |
| ④ | 캡처 + 드래프트 | `04_영상소스/capture.mp4` + CapCut 드래프트 | 헤드리스 통녹화(Step 7) → 3트랙 자동 조립(Step 8). 사용자는 검수·내보내기만 |
| ⑤ | (선택) 영상 소스 오버레이 | `04_영상소스/ov<n>.mp4` | 사용자 제공 시연/실사 영상을 나레이션 구간에 배속 인코딩(Step 6.5) — 드래프트가 4트랙이 된다 |
| ⑥ | 캡컷 조립 재료 | `캡컷 조립 재료/` | 조립·검수에 필요한 파일만 모은 폴더(Step 8.5 — 하드링크): narration.m4a·full.srt·capture.mp4·ov*.mp4·편집지시서·타임라인 |
| ⑦ | 기획 브리프 | `01_대본/BRIEF.md` | **의도 계층**(Step 0.5) — 메시지·타깃·목표·앵글·톤·금지 + 채택된 비주얼 텔링. 규격 = [스토리보드-규격.md](스토리보드-규격.md) §1 |
| ⑧ | 연출 스토리보드 | `04_영상소스/STORYBOARD.md` | **연출 계층**(Step 4) — 프레임별 역할·설득 기법·감정 비트·샷 시퀀스(나레이션 단어 큐). 편집지시서·타임라인.json의 **상류**. 규격 = [스토리보드-규격.md](스토리보드-규격.md) §2 |

음성·자막·영상 3자료는 **동일 타임베이스**를 공유한다 (아래 싱크 계약) — Step 8이 이를 CapCut 드래프트로 합쳐 놓는다.

마지막으로 Step 9·9-2에서 `01_대본/` 대본 파일 끝에 **'영상 요약'(영상 설명/챕터, 첫 줄 고정 해시태그) 섹션**과 **'썸네일 생성 프롬프트' 섹션**을 더한다 — 챕터 시간은 만들어진 영상 소스(타임라인.json) 기준이며, 사용자가 업로드할 때 설명·타임스탬프·썸네일 재료로 그대로 쓴다.

## 🔴 하지 않는 것

- **최종 영상 합성/내보내기(export) 금지** — 완성본을 만들지 않는다. 드래프트 검수·미세조정·내보내기는 사용자가 CapCut에서 직접 한다. (Step 7의 capture.mp4는 소재 캡처이지 완성본이 아니다)
- **배속 변환 금지** — 모든 타임코드는 원본 오디오 시간 그대로 쓴다. (예외: **영상 소스 오버레이의 비디오**는 Step 6.5에서 구간 길이에 맞춰 배속 인코딩한다 — 오디오·자막·슬라이드 타임코드는 여전히 원본 오디오 기준 불변)
- Remotion/Node 빌드 불필요 — 슬라이드는 브라우저에서 바로 열린다.

## 🔒 싱크 계약 (3자료 동기화 원칙)

최종 영상 = [음성 + 자막 + 영상 소스]를 CapCut 드래프트로 합쳐 완성한다 (자동 조립 Step 8, 수동 조합은 폴백). 3자료는 **동일 타임베이스(t=0 = 음성 시작)** 를 공유해야 한다:

| 자료 | t=0 | 타이밍 출처 |
|------|-----|------------|
| 음성 (`02_음성/`) | 트림본(`.trim.m4a`) 시작 | 트림본 그대로 — 배속 없음. 유일한 오디오 편집 = Step 1.5 결정론 무음 컷 |
| 자막 (`full.srt`) | 음성과 동일 | `transcript.json` (STT 실측) |
| 영상 소스 (`presentation.html`) | 오토플레이 시작 순간 | `SLIDE_TIMELINE` = transcript 기준 타임코드 |

- **워크플로우는 녹음이 먼저다**: 음성 → 무음 컷(Step 1.5) → STT(transcript) → 자막 → 영상 소스 순. 슬라이드 타이밍은 대본 추정이 아니라 **실제 발화(transcript.json)** 기준으로 확정한다. 무음 컷이 STT **앞**에 있어서 자막·슬라이드·캡처가 전부 트림본 타임베이스에서 파생된다 — 동기화 후처리가 필요 없는 이유.
- 영상 소스는 **캡처 모드(`?capture=1`)로 헤드리스 프레임 캡처**한다(Step 7) — 프레임마다 `__capture.seek(t)`로 SLIDE_TIMELINE을 적용하므로 mp4의 프레임 0 = 오디오 0초가 구조적으로 보장된다. 수동 폴백: `A` → SPACE 화면 녹화 (SPACE 누르는 순간 = 0초).
- 음성 없이 요청받으면: 슬라이드 초안까지만 만들고, 타임라인(SLIDE_TIMELINE·편집지시서·타임라인.json)과 캡처·조립은 녹음 후 확정한다고 안내한다.

## 결과물 폴더 저장 규약

모든 산출물은 `결과물/YYYY-MM-DD_<주제-슬러그>/`에 저장한다 (구조는 CLAUDE.md·`결과물/README.md` 참조).

1. 작업 시작 시 해당 작업 폴더가 있는지 확인 — 없으면 구조 생성 + `작업정보.md` 작성
2. 산출물이 생길 때마다 `작업정보.md`의 산출물 체크리스트와 상태를 갱신
3. 슬라이드에 쓰는 이미지/로고는 `04_영상소스/` 안에 함께 저장 (상대경로 참조)

**외부 기초 자료 규칙 (산출 위치는 결과물/ 고정 — 2026-07-15 사용자 결정)** — 사용자가 자기 프로젝트 폴더(예: `MY_Ian/1. Project/풀링_011/`)에 기초 자료(`대본/` + `녹음본/` + 선택 `영상 소스/`)를 준비해 지정해도, 그 폴더에 산출하지 않는다. **`결과물/YYYY-MM-DD_<주제-슬러그>/` 작업 폴더를 새로 만들고 기초 자료를 복사해 온 뒤 모든 산출물을 그 안에 만든다**: 대본 → `01_대본/`, 녹음본 → `02_음성/`(사본+트림본+narration.m4a), 영상 소스 → `영상 소스/`(오버레이 원본). 외부 기초 자료 원본은 읽기만 하고 절대 수정하지 않는다 — '영상 요약'·'썸네일 생성 프롬프트' 섹션 append(Step 9)도 **작업 폴더의 대본 사본에만** 한다.

### Step 0.5: 기획 브리프 (BRIEF.md — 의도 계층, 2026-08-27 신설)

대본에서 슬라이드로 직행하지 않는다. 먼저 **"이 영상을 어떻게 보여줄까"**를 파일로 고정한다 → `01_대본/BRIEF.md`.

**파일 규격(프론트매터 8키 · 본문 3절 · 채움 절차 · 피치 3~5안 규칙)은 [스토리보드-규격.md](스토리보드-규격.md) §1이 정본이다.** 여기서는 실행 포인터만 둔다:

2. **비주얼 텔링 피치 3~5안**을 만든다 — 같은 대본을 다르게 보여주는 방식. **최소 2안은 뻔하지 않은 경로**, **5안 전부 제시 후 추천 1안 지목**. 채택안이 `visual_concept`.

### Step 1.4: 녹음 품질 게이트 (결정론 — 트림 전에 반드시)

`python scripts/check_audio.py 02_음성/` — 트루피크·클리핑 흔적·라우드니스를 수치로 판정한다. **경고가 있으면 트림·STT로 넘어가기 전에 사용자에게 알린다**(재녹음 권고: 입력 게인 -6~-10dB, 피크 -6 dBFS 목표). 근거: 2026-08-17 풀링012·013 실측 — "녹음이 깨지는" 원인은 파이프라인이 아니라 **녹음 원본의 입력 게인 과대**(트루피크 -0.1 dBTP, 0dB 근접 런 수십 회)였고 trim·concat·final은 원본을 그대로 보존했다(라우드니스 동일, 프레임 드롭 0, SSIM 0.995+, A/V 드리프트 0.03s). 재녹음이 불가하면 완성본 렌더의 -1 dBTP 리미터(render_final.py 기본 ON, `--no-limiter`로 끔)가 재생 오버슈트만 막는다 — 잘린 파형은 복원 못 한다.

### Step 1.5: 무음 컷 (결정론)

긴 무음(≥1.0s)을 양끝 0.3s만 남기고 0.6s로 압축한다 — 목적은 러닝타임 단축이 아니라 **시청 템포 체감**(늘어짐 제거). 판정·컷·가드는 전부 `scripts/trim_silence.py`가 결정론적으로 수행한다(AI 귀대중 금지).

```bash
python scripts/trim_silence.py "결과물/<작업>/02_음성/녹음-1.m4a" "결과물/<작업>/02_음성/녹음-2.m4a"
# 파일별 <이름>.trim.m4a 생성 + 컷 리포트 + 03_자막/silence_cut_plan.json(컷 플랜·src↔dst 매핑)
python scripts/trim_silence.py "결과물/<작업>/02_음성/녹음-1.m4a" --analyze   # 컷 없이 문턱 스윕(캘리브레이션)
```

- **반드시 Step 2(전사) 이전에** 실행한다. 트림본을 전사해야 자막·슬라이드·캡처가 트림본 타임베이스에서 파생된다. 이미 만들어진 SRT/타임라인이 있는 상태에서 오디오만 다시 트림하면 싱크가 깨진다 → 그 경우 **재전사부터 전부 다시**.
- 기본 파라미터: `--min-gap 1.0`(무음 판정) / `--pad 0.3`(양끝 보존) / `--noise -35`(dB 문턱). **비파괴** — 원본은 그대로, 이후 파이프라인의 정본은 `.trim.m4a`. 컷 0건이어도 스트림 복사로 `.trim.m4a`를 만들어 하류 입력을 균일화한다.
- **검수: 리포트만 출력하고 자동 진행**(파라미터 검증 완료 — 2026-07-08 실녹음 1편 11파일 테스트 통과). 컷 리포트(컷 개수·삭감 초·최장 컷·타임스탬프)를 출력한 뒤 미리듣기 확인 없이 Step 2로 진행한다. 단, 삭감률이 상한(20%)에 걸려 스크립트가 중단되면 사용자에게 알리고 `--analyze`로 문턱을 재조정한다.
- 알려진 트레이드오프: ① 강조용 긴 뜸도 0.6s로 평탄화 — 컷 리포트의 타임스탬프로 위치를 안내하고 필요 시 CapCut 검수에서 되살린다(원본 보존). ② 숨소리가 문턱을 넘으면 컷이 누락되는 방향(언더컷)으로 실패한다 — 말이 잘리는 방향이 아니며, Step 2 후 `--verify`(아래)로 관측한다.

### Step 2: Whisper 전사

`OPENAI_API_KEY`는 `.env`에서 읽는다. (Windows: `python3` 대신 `python`/`py -3`) **전사 대상은 항상 트림본(`.trim.m4a`)이다 — 원본 전사 금지.**

```bash
curl https://api.openai.com/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F file="@결과물/<작업>/02_음성/녹음-1.trim.m4a" \
  -F model="whisper-1" \
  -F response_format="verbose_json" \
  -F "timestamp_granularities[]=word" \
  -o "결과물/<작업>/03_자막/transcript.json"
```

`transcript.json`(단어 타임스탬프 원본)은 쇼츠 컷 계산에도 재사용하므로 반드시 보존한다.

- **전사 직후 읽기 뷰 생성**: `python scripts/pack_transcript.py "결과물/<작업>"` → `03_자막/transcript_packed.md`(구 단위, 무음 갭 ≥0.4s는 `✂` 컷 후보 표시, 파일 경계 표시). 이후 단계(스토리보드 Scene 큐·쇼츠 컷 선정)에서 발화 흐름·갭을 볼 때는 transcript.json 원문 대신 이 파일을 먼저 읽는다 — 시각 실측은 여전히 transcript.json 단어 타임스탬프가 정본이다.

- **API 실패 시 로컬 폴백**: `billing_not_active` 등으로 API를 못 쓰면 로컬 `openai-whisper`(pip, small 모델)로 전사한다. ffmpeg은 `imageio_ffmpeg.get_ffmpeg_exe()`를 `ffmpeg.exe`로 복사해 PATH에 넣으면 된다. 타임코드는 실측이므로 싱크 품질은 동일하고, 텍스트 오인식은 Step 3에서 대본 대조로 보정된다.
- **녹음이 여러 파일이면**: 트림본별로 전사한 뒤 누적 오프셋(앞 트림본들의 디코드 길이 합)을 더해 단일 타임베이스로 병합한다. transcript.json에 `files`(오프셋 목록)를 기록하고, ffmpeg concat(코덱 복사)으로 **트림본들의** `02_음성/narration.m4a` 단일 파일도 만들어 둔다 (Step 8 조립 입력). 파일별 전사 유지 = whisper API 25MB 제한 회피(트림으로 파일이 더 작아진다).
- **전사 직후 언더컷 관측(report-only)**: 트림이 정상이면 단어 갭은 ≈0.6s 이하여야 한다. 큰 갭이 남았으면 숨소리가 문턱을 넘어 무음 런이 쪼개진 것 — 다음 영상에서 `--noise` 조정 근거로만 쓴다(게이트 아님).

  ```bash
  python scripts/trim_silence.py --verify "결과물/<작업>/03_자막/transcript.json"
  ```

### Step 3: SRT 생성 (보정 규칙) + 16자 강제

**3a. AI가 transcript.json을 직접 분석해 SRT를 작성한다 (의미 보정만):**

- **자연스러운 구/문장 단위로 묶는다** — 단어 단위 ❌. **글자수(16자)를 손으로 맞추려 하지 마라.** 분할은 3b 스크립트가 한다.
- **타임코드는 원본 오디오 시간 그대로** (배속 변환 없음). **transcript.json은 불변** — 아래 교정·보정은 전부 full.srt에만 (Whisper 원본은 쇼츠 컷 계산에 재사용).

**3a-2. 교정 사전을 기계 적용한다 (반복 오인식은 프롬프트가 아니라 사전이 잡는다 — 16자 캡과 같은 구조적 강제):**

```bash
python scripts/apply_corrections.py "결과물/<작업>/03_자막/full.srt"   # 레퍼런스/교정사전.json 치환 + 적용 리포트
```

- 텍스트만 치환하고 순번·타임코드 라인은 건드리지 않는다(싱크 불변). 반드시 **3b(16자 분할) 이전**에 — 치환으로 컷이 16자를 넘을 수 있고, 그 분할은 3b가 책임진다.
- **AI는 사전 밖 오류만 대본 대조로 보정**: 잘못 분리·오인식된 단어 수정 (예: "1호는" → "이론은"), 분리 단어 합치기 ("보도" + "자료를" → "보도자료를")
- **반복 관측되지만 사전에서 제외된 오인식 — 매번 여기서 확인**: "구동료"→"구독료", "일대일"→"1대1", "이한에게"→"이안에게", "채 지피티"→"챗GPT", "재미나이"→"제미나이", "울트라 코드"→"울트라코드" (substring 오탐 우려로 사전 제외 결정 2026-07-06 — 대본 대조로 확인 후 수정)
- **수확(등재)**: 보정 중 새로 발견한 오인식 중 **어떤 문맥에서도 치환이 항상 옳은 것만** `레퍼런스/교정사전.json`의 `replace`에 추가한다 — 다음 영상부터 기계가 잡는다. 판단 기준: 오인식 문자열이 한국어에서 다른 의미로 성립할 가능성이 조금이라도 있으면(인명·복합어·의존명사 조합 등) **등재하지 말고 위 주의 목록에 추가**한다(매 영상 AI 보정 — 2026-07-06 사용자 결정). 🔴 동음이의·문맥 의존 교정("다쳐서"→"다 차서", "지었다고"→"지녔다고" 류)은 **등재 금지**(다른 영상을 오염시킨다) — 해당 영상 한정 AI 보정으로만.

**3b. 16자 하드 캡을 스크립트로 강제한다 (프롬프트 아님 — 구조적 강제):**

```bash
python scripts/split_captions.py "결과물/<작업>/03_자막/full.srt"   # 16자 초과 컷을 어절 경계로 분할(.raw.srt 백업)
python scripts/split_captions.py "결과물/<작업>/03_자막/full.srt" --check   # 검증: 초과 컷 0 확인
```

- 한 컷 ≤16자(공백 포함)는 타이포 제약이라 LLM이 100+컷 중 일부를 반드시 어긴다 → **결정론적 스크립트가 보장**한다. AI는 자연스러운 구로만 묶고, 16자 분할은 스크립트에 맡긴다.
- 분할 컷의 시간은 **원래 컷 구간 안에서** 글자수 비례 배분 → 음성·SLIDE_TIMELINE·타임라인.json 싱크 불변(자막 컷 수만 늘어남).
- `assemble_capcut.py`(Step 8)도 임포트 직전 같은 강제를 멱등으로 한 번 더 돌린다 — Step 3b를 빠뜨려도 최종 드래프트는 항상 ≤16자. 규격·근거: [자막-안전영역.md](자막-안전영역.md).

**분업 절차 (7프레임 이상일 때 — 규약 정본 = [스토리보드-규격.md](스토리보드-규격.md) §3):**

- **프레임 패킷**(48KB 상한) = ① 해당 `## Frame NN` 블록 전문 ② `blueprint`가 가리키는 부품 본문 ③ 걸리는 rule 본문(교리 4법칙 해당 조항·쓰는 preset의 렉시콘 행·4색·한글·자막 안전영역 21vh)을 **인라인으로**. 링크만 주지 않는다.
- **캔버스 카메라 프레임(`route: camera-with-intent`)의 패킷**에는 감독이 **레이아웃 좌표(1920×850 기준)와 카메라 계획(`.tgt` 사각형·shot/fit 시각·이동 이유)**을 지급한다. 워커는 `shot/fit` 값을 바꾸지 않고, 요소 리빌만 만든다(2026-09-14).
- 🔴 **워커는 STORYBOARD 전체를 열지 않는다** — 패킷이 전부다(전체를 읽히면 워커가 편 전체 판단을 시작해 후반부 품질이 떨어진다).
- **워커 출력 계약** = `<section class="slide">` 조각 1개 + 그 슬라이드의 로컬 GSAP 타임라인 1개. 전역 CSS·SLIDE_TIMELINE·캡처 블록·타임라인.json은 **감독만** 건드린다.
- **감독 조립**: 조각을 순서대로 합치고 → 프레임 간 **벡터 연속성**(연속 역방향 금지, design.md §4 벡터 예약표)을 검수하고 → 게이트로 넘긴다. 워커는 옆 프레임을 모르므로 벡터 연속성은 감독 전담.
- **모델 규칙**: 판단(브리프·스토리보드·최종 검수) = 메인 세션, 프레임 제작 노동 = 위임(기본 opus). 워커의 "이상 없음"을 최종 증거로 쓰지 않고 표본 감사한다.

### Step 6: 동기화 데이터 (편집지시서 + 타임라인.json)

슬라이드별로 어떤 오디오 구간에 해당하는지 매핑한다. 타임코드는 transcript.json 기준. 같은 데이터를 사람용(MD)과 기계용(JSON) 두 형식으로 저장한다.

```markdown
# 편집지시서 — <작업명>

- 오디오: 02_음성/narration.m4a (트림본 무갭 concat, 총 14:32) — 원본 속도(1.0x), 무음 컷(Step 1.5) 적용본
- 영상 소스: 04_영상소스/presentation.html (총 52장) → capture.mp4 (헤드리스 캡처)
- 자막: 03_자막/full.srt — 드래프트에 임포트됨 (스타일 미세조정: 자막-안전영역.md 참조)
- CapCut 드래프트: '<작업명>' — 3트랙(나레이션/영상소스/자막) 조립 완료

| # | 슬라이드 | 오디오 구간 | 길이 | 내용 요약 | 연출 (렉시콘) |
|---|---------|------------|------|----------|--------------|
| 1 | S01 타이틀 | 00:00.0–00:08.4 | 8.4s | Hook 첫 문장 | 스태거 → 와이프 리빌(제목) |
| 2 | S02 비교 바 | 00:08.4–00:21.0 | 12.6s | 문제 제시 — 비용 비교 | 그로우 인(바) + 카운터 |
| ... |

연출 컬럼은 **design.md §4 모션 렉시콘 용어로만** 기술한다 (자유 서술 금지 — 용어=구현 클래스 1:1이라 검수 시 그대로 대조 가능).

## CapCut에서 할 일
1. CapCut 열기 → 드래프트 '<작업명>' 선택 — 3트랙이 이미 조립돼 있음
2. 검수: 슬라이드 전환·자막 싱크 확인 → 미세조정(전환 효과, 자막 스타일) → 내보내기

## 수동 조합 (자동 조립 실패 시 폴백)
1. presentation.html 열기 → F 전체화면 → 화면 녹화 시작 → A → SPACE (누르는 순간 = 오디오 0초)
2. CapCut: 커버가 사라지는 프레임을 오디오 시작에 맞춰 배치 → full.srt 임포트
3. 부분 재녹화: ?start=초 로 중간부터 재생
```

`타임라인.json` (같은 데이터의 기계용 — CapCut 드래프트 자동 조립(Step 8)의 입력, 작업 폴더 루트에 저장):

```json
{
  "type": "main",
  "timebase": "오디오 t=0 기준 초",
  "audio": "02_음성/narration.m4a",
  "srt": "03_자막/full.srt",
  "transcript": "03_자막/transcript.json",
  "source_html": "04_영상소스/presentation.html",
  "duration": 872.4,
  "slides": [
    { "id": "S01", "index": 0, "start": 0.0, "end": 8.4, "label": "타이틀" },
    { "id": "S02", "index": 1, "start": 8.4, "end": 21.0, "label": "비용 비교", "stages": [{ "stage": 1, "start": 15.2 }] }
  ],
  "video_overlays": [
    { "n": 1, "src": "영상 소스/1.mp4", "start": 0.5, "end": 6.0, "src_dur": 4.667, "label": "영상1 · Hook(주간 사용량 한도)" }
  ]
}
```

`video_overlays`(본편은 항상 존재 — 콜라주 오프닝이 필수라 최소 1항목; 실사 오버레이는 선택): `n`=오버레이 번호(ov<n>.mp4), `src`=사용자 원본(작업 루트 기준 상대경로), `start`/`end`=**오디오 타임베이스**의 배치 구간(초), `src_dur`=원본 길이(encode_overlays.py가 실측으로 갱신), `label`=내용 한 줄. `style`(선택)=`"whiteboard"`면 화이트보드 드로잉 클립(Step 6.6) — 흰 배경이라 겹치는 자막을 흰색으로 바꾸지 않고 잉크색 유지(assemble_capcut.py·render_final.py 공통). `style`=`"collage"`면 콜라주 인서트(Step 6.7) — `scene` 필드(콜라주 대본 JSON 경로) 필수, encode_overlays.py는 건너뛴다. `style`=`"hyperframes"`면 HF 히어로 인서트(Step 6.8) — 렌더는 `render_hf.py`, encode_overlays.py는 건너뛴다(콜라주와 합산해 오버레이 총량 ≤ 러닝타임 25%). **본편은 `start: 0.0`인 콜라주 오프닝 항목이 반드시 하나 있어야 한다**(validate_pipeline 검사 F). 실사 오버레이는 `style` 생략.

### 영상 소스 오버레이 (사용자 제공 시연/실사 영상) — 오버레이 모드

사용자가 `영상 소스/N.mp4`(화면 녹화 등)와 `대본/대본 중 영상 소스 활용할 곳.md`(각 영상이 얹힐 대본 발췌)를 주면, 해당 나레이션 구간 위에 실사 영상을 얹는다. 레퍼런스 산출물: 풀링_011.

1. **구간 매칭 (Step 6에서)** — '활용할 곳' 문서의 대본 발췌를 transcript.json의 실제 발화에서 찾아 각 영상의 `[start, end]`를 확정한다(추정 금지 — 단어 타임스탬프 실측). 구간은 보통 해당 슬라이드 경계와 일치시킨다.
2. **폴백 슬라이드** — 오버레이가 덮는 구간에도 **대응 슬라이드(오프닝/사용법 카드)를 만들어 밑에 깔아 둔다**. 오버레이를 지우거나 옮겨도 화면이 비지 않는다.
3. **배속 인코딩 (Step 6.5)** — `python scripts/encode_overlays.py <타임라인.json>`: 컷 없이 **배속만**으로 구간 길이에 맞춘다(화면 녹화는 액션 흐름이 나레이션과 이미 일치). 화면비 보존 + 1920x1080 흰 패딩 + 무음. 배속 가드 0.5~2.0×(밖이면 구간 배정 오류 의심 — 중단).
4. **조립 (Step 8)** — assemble_capcut.py가 `video_overlays`를 자동 인식해 4트랙(나레이션/슬라이드/영상소스/자막)으로 조립하고, **오버레이와 겹치는 자막 컷만 흰색**(실사 위 가독성), 나머지는 잉크색으로 넣는다.
5. **편집지시서** — 오버레이 표를 추가한다: 영상 | 구간(오디오) | 구간 길이 | 원본 길이 | 배속 | 내용. 폴백 슬라이드 관계도 명시(풀링_011 편집지시서 형식).

### Step 6.6: 화이트보드 드로잉 장면 (⏸ **비활성 — 2026-08-16 오너 결정. 이 단계는 건너뛰고 제안하지 않는다.** 켜는 법 = `scripts/whiteboard/README.md`)

스토리·비유·개념 설명처럼 **수치가 없는 대목**에서, 슬라이드 위에 "손+마커가 4색 선화를 순서대로 그려 나가는" 클립을 얹는다(design.md §4 렉시콘 "화이트보드 드로잉"). 렌더 엔진은 `scripts/whiteboard/`(geeklee/srt-whiteboard-animation vendoring, MIT), 장면 규칙·프롬프트는 `템플릿/whiteboard/README.md`. **기본은 미사용** — 결정 트리에서 해당 대목이 있을 때만, 🔒 영상당 1~3장면·장면당 8~30초.

1. **장면 고르기 (Step 4에서)** — 슬라이드 분해 때 후보 대목을 표시하고, 그 아래에는 **폴백 슬라이드**를 그대로 만든다(오버레이 규칙과 동일 — 클립을 빼도 화면이 비지 않는다). 구간은 `start` = 해당 슬라이드 시작, **`end` = 다음 슬라이드 시작 + 0.45s**(클립 끝이 흰색으로 페이드되며 슬라이드 디졸브를 덮는다 — 경계에서 뚝 끊으면 반쯤 섞인 프레임이 보여 어색).
2. **장면 SVG 작성** — `템플릿/whiteboard/scene-example.svg`를 `04_영상소스/wb-scenes/wb<n>.svg`로 복사해 그린다. 규칙(흰 배경·4색·글자 없음·하단 21% 비움·`data-wb="N"` 순서·선택 `data-wb-t`)은 README 그대로. 복잡한 장면은 외부 이미지 생성 PNG + `--annotation`/`--auto`(README의 프롬프트 골격).
3. **렌더** — `python scripts/render_whiteboard.py 04_영상소스/wb-scenes/wb<n>.svg --out 04_영상소스/wb<n>.mp4 --duration <end-start>` → 1920x1080·30fps·무음·정확한 길이. 하단 안전 영역에 잉크가 있으면 중단(fail-loud). 소요 ≈ 클립 길이 × 9.
4. **타임라인 등록** — `video_overlays[]`에 `{ "n", "src": "04_영상소스/wb<n>.mp4", "style": "whiteboard", "start", "end", "label" }` 추가(실사 오버레이와 같은 배열, n은 통합 번호). 이후는 오버레이 모드와 동일: `encode_overlays.py`(배속 1.000× — 아니면 duration 오기입) → Step 7 캡처 → Step 8 조립(자막은 잉크색 유지).
5. **편집지시서** — 오버레이 표에 `종류=화이트보드` 열로 함께 기재하고, 장면이 어떤 대본 문장을 그리는지 한 줄 적는다.

실측 판단 기준(오너): 완성본에서 ① 그려지는 속도가 나레이션과 맞는가 ② 흰 배경 슬라이드와 이질감이 없는가 ③ 손 자산이 어색하지 않은가. 별로면 `scripts/whiteboard/README.md` 롤백 절차(태그 `pre-whiteboard-2026-08-16`).

### Step 6.7: 콜라주 인서트 (페이퍼 컷아웃 콜라주 — **오프닝 필수 + 본문 1~2개**)

색종이 배경 위에 "신문·잡지에서 오려낸 종이 조각을 하나씩 붙이는" 스톱모션 룩의 인서트를 얹는다. 렌더 엔진은 별도 레포 `공유 프로젝트/cutout-collage-lab`(Remotion, 대본 스키마 = 그 레포 `src/schema.ts`·`README.md`), 실행은 `scripts/render_collage.py`.

**🔒 오프닝 콜라주 필수 (오너 결정 2026-08-18)** — 영상의 **가장 첫 장면(t=0)은 반드시 콜라주 인서트**로 연다. 이유: 콜라주는 첫 1~2초 안에 손맛·색종이 질감으로 시선을 잡아 시청 시작 시점의 후킹·몰입에 가장 강하다(흰 슬라이드 타이틀로 시작하면 이 효과를 버린다). 편당 콜라주 인서트는 **2~3개 = 오프닝 1개(필수) + 본문 1~2개**이며, 오프닝은 `start: 0.0` 고정, `end` = 훅 문장(대본 첫 1~2문장)이 끝나는 슬라이드 경계(보통 S01 또는 S01+S02, 5~20초). `render_collage.py`와 `validate_pipeline.py`(검사 F)가 오프닝 부재·4개 이상을 기계로 막는다(fail-loud).

**본문 인서트 결정 트리 — 아래 셋 중 하나에 해당하는 대목에서 1~2개:**
① **실패담·에피소드 서사** — 사물·사건이 하나씩 등장하며 이야기가 쌓이는 대목 ② **항목 나열·비교** — 2~3개 항목이 나란히 놓이는 대목 ③ **수치·비율** — 종이 파이·코인 막대로 보여줄 데이터. **금지**: 화면 시연·코드 설명·추상 개념 설명 구간(슬라이드·차트가 더 낫다). 🔒 **게이트: 편당 2~3개(오프닝 포함), 본문 인서트 15~45초, 합계 ≤ 러닝타임 25%** (render_collage.py가 25%·오프닝·개수 상한을 기계로 강제). **오너 확정(2026-08-17): 100% 콜라주판과 비교 후 "섞어서 2~3구간만" 방식으로 결정 — 전 구간 콜라주는 만들지 않는다.**

1. **오프닝 대본 (Step 4에서 먼저)** — 슬라이드 분해 때 훅 구간(S01 또는 S01+S02)을 오프닝 콜라주 구간으로 표시하고, 그 아래 슬라이드는 **폴백으로 그대로 만든다**(오버레이 규칙 동일 — 클립을 빼도 화면이 비지 않는다). 오프닝 대본은 훅 문장을 그대로 그림으로 옮긴다: 첫 요소는 **0.3초 안에** 등장(빈 배경 금지·"탁" 붙는 place/pop), 훅의 핵심 명사·말풍선·물음표를 나레이션 어절 시각에 맞춰 붙이고, 훅이 던진 질문/대비가 화면에 남은 채로 끝낸다(다음 슬라이드가 답을 잇는다).
2. **대본 작성** — `04_영상소스/collage/cg<n>.json` (lab 스키마). 씬 duration 합 = 오버레이 구간(end−start)과 정확히 일치. **caption 필드 금지** — 본편이 흰 상자 자막을 굽는다. 요소 등장 시각은 해당 나레이션 어절 타임스탬프에 맞추고, 첫 요소는 0.5초 안에 등장시킨다(오프닝은 0.3초).
3. **타임라인 등록** — `video_overlays[]`에 `{ "n", "src": "04_영상소스/ov<n>.mp4", "start", "end", "style": "collage", "scene": "04_영상소스/collage/cg<n>.json", "label" }`. 오프닝은 `start: 0.0`. src는 렌더 산출물 자신을 가리킨다(검증 D·E 통과용). encode_overlays.py는 collage 항목을 건너뛴다.
4. **렌더** — `python scripts/render_collage.py <작업 폴더>` → 오프닝·개수·25% 게이트 → 겹침 검사(lab tools/check_layout.py --strict) → Remotion 렌더 → `04_영상소스/ov<n>.mp4` (1920x1080·30fps·무음·bt709·정확한 길이).
5. **편집지시서** — 오버레이 표에 `종류=콜라주(오프닝)` / `종류=콜라주` 로 기재하고, 어떤 대본 문장 구간인지 한 줄 적는다.

### Step 6.8: HF 히어로 인서트 (선택 연출 — 2026-08-27 신설)

HyperFrames(HeyGen, Apache-2.0) 렌더러로 만든 **짧은 히어로 클립**을 콜라주와 같은 자리(오버레이 트랙)에 얹는다. 본편 렌더러는 그대로 두고 **인서트 단위로만** 쓴다.

**🔒 게이트**: 대상은 **훅 보조 · 파트 타이틀 · 데이터 클라이맥스 · 엔딩 CTA** 중 **편당 0~2곳**. **콜라주와 합산해 오버레이 총량 ≤ 러닝타임 25%**(기존 25% 게이트에 합산 — 별도 예산이 아니다). 기본은 미사용 — Step 4 스토리보드에서 해당 대목을 지목했을 때만.

1. **프로젝트 스캐폴드** — `04_영상소스/hf/<n>/`에 HF 프로젝트를 만든다. 핀 버전 고정, **로컬 GSAP**, Pretendard는 `@font-face url()`로 임베드, 폴백 폰트마다 `src: local()` 스텁. 길이는 구간과 일치하게 루트 `data-duration`에 **정적 기입**한다.
2. **팔레트** — design.md 4색 그대로. 🔴 **HF `check`의 명암비 임계는 변경 불가**(큰 텍스트 3:1, 작은 텍스트 4.5:1) — 흰 배경 위 `#F59E0B` 텍스트는 2.15:1로 **실패**한다. 텍스트는 기존 규칙대로 `#D97706`(큰 텍스트)를 쓴다. 더 작은 텍스트 강조로 `#b06f07`을 검토 중이나 **아직 미채택** — 색을 추가하려면 design.md에 먼저 등재해야 한다(색상 규칙의 SSOT는 design.md뿐).
3. **렌더 전 게이트** — `lint → check → snapshot` 순으로 통과시킨 뒤 렌더한다.
4. **렌더** — `python scripts/render_hf.py <작업 폴더>` (내부적으로 `npx --yes hyperframes@0.8.16 render . --output ../ov<n>.mp4 --fps 30 --quality high --workers 1`, Windows에서는 `npx.cmd` 명시). **무음 렌더** — 오디오는 CapCut 트랙이 소유한다.
5. **타임라인 등록** — `video_overlays[]`에 `{ "n", "src": "04_영상소스/ov<n>.mp4", "start", "end", "style": "hyperframes", "label" }`. **`encode_overlays.py`는 hyperframes 항목을 건너뛴다**(콜라주와 동일).
6. **편집지시서** — 오버레이 표에 `종류=HF 인서트`로 기재하고 어떤 대본 문장 구간인지 한 줄 적는다.

🔴 `npx hyperframes` 계열 명령은 항상 `HYPERFRAMES_SKIP_SKILLS=1 HYPERFRAMES_NO_TELEMETRY=1`과 함께 실행한다(init이 홈의 에이전트 폴더에 스킬을 무단 복사한다). CLI는 실행 폴더의 `.env`를 자동 로드하므로 **워크스페이스 루트에서 직접 돌리지 않는다**(API 키 노출).

### Step 7: 헤드리스 캡처 (HTML → capture.mp4)

CapCut은 HTML을 읽지 못하므로 영상 소스를 mp4로 캡처한다. 템플릿의 캡처 모드(`?capture=1`)와 `scripts/capture_slides.py`가 처리한다:

```bash
python scripts/capture_slides.py "결과물/<작업>/04_영상소스/presentation.html" --timeline "결과물/<작업>/타임라인.json"
```

- **frames 모드(기본)**: BeginFrame 제어 + CDP 가상시간으로 프레임마다 ① `__capture.seek(t)`가 덱 상태를 직접 구동 ② `HeadlessExperimental.beginFrame`이 합성+스크린샷 → ffmpeg 파이프 인코딩. **고정 30fps, 프레임 드랍 없음, 프레임 0 = t=0** (blackdetect 불필요). 슬라이드 모션(스태거·차트 애니메이션)은 가상시간을 따라 그대로 보존된다.
- 해상도: main 2560x1440 / short 1440x2560 기본 (`--size`로 변경). 레이아웃은 1080p 디자인 그대로 — 전역 DSF(`--force-device-scale-factor`)로 픽셀만 키우므로 요소 비율이 변하지 않는다.
- 소요: 실시간이 아니라 스크린샷 속도 비례 (6분 영상 ≈ 10~20분). **10분 넘는 작업은 분리 프로세스(Start-Process)로 실행**하고 로그(capture.log)를 폴링한다.
- 의존성: `playwright`(+chromium), `imageio-ffmpeg` (pip). 구버전 HTML(`__capture.seek` 없음)은 `--mode realtime` 폴백 (VFR·저화질 — 비권장).
- 🔴 **page.screenshot()·Page.captureScreenshot은 BeginFrame 제어와 함께 쓰지 않는다** — 행/시계 오염 (frames 모드 구현이 이미 처리).

### Step 7.5: 모션 게이트 (캡처 직후 — 2026-08-27 신설)

"슬라이드 시간의 80~90%가 정지 화면" 회귀를 기계로 막는다. 육안 가정 금지.

```bash
python scripts/check_motion.py "결과물/<작업>/04_영상소스/capture.mp4" --timeline "결과물/<작업>/타임라인.json"
python scripts/hf_audit.py "결과물/<작업>/04_영상소스/presentation.html"   # 선택 — 레이아웃·명암비 DOM 감사
```

- `check_motion.py`: capture.mp4 프레임 차분을 **1초 격자**로 측정해 슬라이드별 정지 초 비율이 임계를 넘으면 경고/실패. 컷 경계 전후 4프레임의 변위 부호로 **죽은 박자**(감속해 멈춘 뒤 넘기는 전환)를 근사 판정한다.
- `hf_audit.py`(선택): HF `check`의 브라우저 스크립트(layout/contrast/motion)를 `presentation.html`에 주입해 **레이아웃 겹침·잘림·명암비**를 전수 검사한다(한글 라벨 상수는 8자로 재보정된 값 사용).
- `timeline_view.py`(선택, WARN 원인 분류용): `python scripts/timeline_view.py "결과물/<작업>" <start> <end>` → `검증/timeline_<s>-<e>.png`(필름스트립+프레임 차분 띠+파형+단어 큐+갭 밴드+슬라이드/오버레이 경계선)과 같은 이름 `.json`(수치). WARN·죽은 박자가 뜬 슬라이드 경계 ±3s만 뜬다 — 상시 스캔 도구가 아니다. 숫자는 JSON으로 읽고 그림은 연속성 판단에만 쓴다.
- 실패하면 **스토리보드로 돌아간다** — 슬라이드 코드에 모션을 덧칠하지 말고, 해당 프레임의 `route`·Scene 창을 고쳐 Step 4.5부터 다시 태운다.

### Step 8: CapCut 드래프트 자동 조립

CapCut은 공식 편집 API가 없다. 대신 프로젝트가 로컬 비암호화 JSON(`draft_content.json`)이므로, **pycapcut**으로 드래프트를 코드 생성한다 — CapCut을 열면 3트랙이 이미 조립돼 있고, 사용자는 검수·미세조정·내보내기만 한다.

```bash
python scripts/assemble_capcut.py "결과물/<작업>/타임라인.json"   # capture.mp4 자동 탐색, --replace로 재조립
```

- **조립 매핑** (모두 타임라인.json 기준): 오디오 트랙 = `02_음성/` 전체(t=0부터, 쇼츠는 audio_cuts대로 컷 배치) / 비디오 트랙 = capture.mp4(t=0부터) / 자막 트랙 = `full.srt` 일괄 임포트 + 하단 배치 + **잉크색(#141413) 자동 적용**(흰 배경 가독성 — 자막-안전영역.md)
- **오버레이 모드(video_overlays 존재)**: 자동 4트랙 — 슬라이드(capture.mp4, 밑) + 영상소스(ov<n>.mp4, 위·구간 정확 트림·무음) + 오버레이 겹침 자막만 흰색. ov 파일이 없으면 중단(encode_overlays.py 먼저)
- **본편 오디오는 단일 파일**이어야 한다 — 녹음이 여러 파일이면 Step 2에서 만든 `narration.m4a`(트림본 무갭 concat)를, 단일 파일이면 그 트림본(`<이름>.trim.m4a`)을 타임라인.json `audio`에 지정. 🔴 **미트림 원본을 지정하지 않는다** — 자막·슬라이드가 트림본 타임베이스라 조용히 어긋난다
- **드래프트 위치**: `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft\<이름>\`
- **내보내기(렌더링)는 자동화하지 않는다** — 전역 규칙(최종 합성 금지) 유지. 어차피 사람 검수가 들어간다.

**주의사항:**

| 항목 | 내용 |
|------|------|
| CapCut 종료 후 작업 | CapCut이 켜져 있으면 드래프트를 덮어쓴다 — 스크립트가 감지해 중단함. 기존 드래프트 수정 시 백업 먼저 |
| 버전 고정 | 국제판 CapCut 9.x까지 비암호화 확인(2026-05 기준) — 작동 버전에서 자동 업데이트 OFF. 드래프트가 암호화돼 있으면 이 방식 불가 → 수동 조합으로 폴백 |
| SRT 인코딩 | UTF-8 필수 (PowerShell로 생성 시 인코딩 명시 — 한글 깨짐 방지) |
| 절대경로 | 소재 경로가 드래프트에 절대경로로 박힌다 — 조립 후 결과물 폴더를 옮기면 링크가 깨진다 (옮겼으면 --replace로 재조립) |
| JSON 직접 편집 금지 | `draft_content.json`을 손으로/에이전트가 직접 수정하지 않는다 (중첩 구조 환각 빈발) — 반드시 pycapcut 스크립트를 거친다 |

### Step 8.5: 캡컷 조립 재료 스테이징

CapCut 조립·검수에 필요한 파일만 작업 폴더의 **`캡컷 조립 재료/`** 한 폴더에 모은다 — 사용자가 이 폴더 하나만 보면 되도록(수동 조합 폴백·타 기기 이동 시에도 이 폴더만 옮기면 됨).

```bash
python scripts/stage_capcut_kit.py "결과물/<작업>/타임라인.json"
```

- 담기는 것: `narration.m4a`(오디오) · `full.srt` · `capture.mp4` · `ov<n>.mp4`(오버레이 있을 때) · `편집지시서.md` · `타임라인.json`
- **하드링크**(같은 볼륨, 용량 0 추가) 우선, 실패 시 복사. 멱등 — 재실행하면 기존 항목을 새로 건다(상류 재생성 후 재실행 권장).
- 드래프트(Step 8)는 원 위치(02_음성/·03_자막/·04_영상소스/)를 절대경로로 참조하므로 이 폴더는 **사람용 모음**이다 — 원본 폴더를 지우면 드래프트 링크가 깨진다(전역 규칙의 '조립 후 이동 금지'와 동일).

### Step 9: 대본에 '영상 요약'(영상 설명/챕터) 섹션 추가

영상 소스·자막·타임라인이 확정되면(Step 1~8 완료), `01_대본/`의 대본 파일 **맨 아래에 '영상 요약' 섹션을 덧붙인다**. 이 블록은 사용자가 업로드할 때 영상 설명·타임스탬프로 **그대로 붙여 쓴다**.

형식·스타일·분량은 레퍼런스 `D:\Workspace\MY_Ian\1. Project\풀링_011\대본\대본_1.md`의 맨 아래 **'영상 요약 (영상 설명 / 챕터)' 섹션을 그대로** 따른다 — **영상 설명 문단(2~3줄) + `챕터` 라벨 + 챕터 타임스탬프 목록**. (구 레퍼런스: 풀링_009 '콘텐츠 정리' — 같은 형식이며 제목만 다르다.)

**입력/대상**
- 대상: `01_대본/script.md` (순수 나레이션 대본 — `기획메모.md`는 대상 아님). 본문은 건드리지 않고 **끝에 섹션만 append**한다. 이미 '영상 요약' 섹션이 있으면 새로 만들지 말고 그 섹션을 교체한다(멱등). (대본 초안에 `## 영상 요약` 자리표시자(제목만 + 타임코드 미정)가 미리 들어 있는 경우도 같은 규칙 — 여기서 실측 타임코드로 교체된다.)
- 챕터 시간 출처: `타임라인.json`(슬라이드 `start`) + `SLIDE_TIMELINE` + 대본 `## Part` 경계. **추정 금지 — 실측 타임코드만 사용**(타임라인.json이 곧 "만들어진 영상 소스"의 시간이다). 음성/타임라인이 아직 없으면(초안 모드) 이 단계는 건너뛰고 녹음·캡처 후 확정한다고 안내한다.

**챕터 만드는 법**
- 각 챕터 = 주제가 바뀌는 지점(대본 Part / 타임라인 토픽 그룹)의 **첫 슬라이드 오디오 `start` 시각**. 첫 챕터는 항상 `00:00`.
- 개수: 주제 전환마다 1개 — 영상 길이에 맞춰 **보통 6~10개**(10~20분 기준). 절대 시간 간격이 아니라 주제 전환을 기준으로 나누고, 너무 잘게 쪼개지 않는다. (레퍼런스는 4~5분 영상이라 5개)
- 시간 포맷: `MM:SS`(1시간 미만), 1시간 이상이면 `H:MM:SS`. 분·초는 영점 패딩(`01:38`).
- 챕터 제목: **호기심 유발형 한 줄**(클릭 유도) — 영상 제목 톤과 일관. 단조로운 목차형(예: "서론", "본론") 금지.

**영상 설명 문단**: 영상이 무엇을 다루는지 2~3줄, 시청자가 얻을 가치로 끝맺음(레퍼런스: "…확실히 정리되실 겁니다."). 분량도 레퍼런스와 비슷하게 짧게.

**고정 해시태그 (섹션 최상단, 변경 금지 — 2026-07-15 사용자 지정)**: 섹션 제목 바로 아래 첫 줄에 아래 텍스트를 **한 글자도 바꾸지 않고 그대로** 넣는다. 주제·영상 내용과 무관하게 항상 이 네 개다:

```
#클로드 #클로드코드 #claudecode사용법 #클로드코드활용
```

대본 파일 끝에 붙이는 형식(레퍼런스 '콘텐츠 정리' 그대로, 제목만 '영상 요약' + 고정 해시태그 첫 줄):

```markdown

---

## 영상 요약 (영상 설명 / 챕터)

#클로드 #클로드코드 #claudecode사용법 #클로드코드활용

[영상 설명 2~3줄 — 핵심 주제 + 시청자가 얻을 가치로 마무리]

챕터
00:00 [도입 — 후킹 한 줄]
01:38 [본론 1 — 호기심 유발 제목]
02:18 [본론 2 — 호기심 유발 제목]
03:00 [본론 3 — 호기심 유발 제목]
03:47 [정리/주의 — 호기심 유발 제목]
```

(레퍼런스 실제 챕터 예시 — 울트라코드 편: `00:00 바이브 코딩 판을 바꾼 클로드 신기능, '울트라 코드'` / `01:38 클로드코드 없이도 가능, 울트라 코드 적용법 완전 가이드` / `02:18 … AI 에이전트 군단 활용법` / `03:00 혼자서 2~3인분, … '바이브 워킹'` / `03:47 무조건 쓰면 손해, … 2가지 함정`.)

### Step 9-2: 대본에 '썸네일 생성 프롬프트' 섹션 추가

대본이 **'썸네일' 파트 + '본문' 파트**로 나뉘어 오는 경우, '영상 요약' 섹션 뒤에 **'썸네일 생성 프롬프트' 섹션을 하나 더 append**한다. 사용자가 썸네일 배경 이미지를 직접 만들 때 이 섹션을 시드로 쓴다(이미지 생성은 사용자 몫 — 이 워크스페이스는 프롬프트까지만).

🔴 **이 단계의 산출물은 '프롬프트 텍스트'뿐이다 — 이미지 생성 호출은 하지 않는다 (2026-07-15 사용자 결정)**. 프롬프트가 묘사하는 대상은 '썸네일 배경 이미지':
- **텍스트 없음** — 멘트는 정해져 있고 사용자가 직접 얹는다. 프롬프트에 "텍스트/글자 넣지 마라"를 명시하고, 멘트가 얹힐 영역의 여백/명암 확보를 지시한다.
- **인물 활용 금지** — 사람 얼굴/신체를 배경에 넣지 않는다.
- **클로드 로고가 필요하면** 모양 참고 원본은 `레퍼런스/로고/claude.png`다 — 프롬프트를 쓰기 전에 이 파일을 **실제로 열어 보고**, 로고의 형태를 프롬프트 안에 정확히 묘사한다.

**절차**
1. 대본 '썸네일' 파트에서 **썸네일 메인 멘트**를 확인한다.
2. 멘트를 클릭 관점에서 분석한다 (4항목 — 전부 본문 도입부와 대조해 근거 있게):
   - **타깃**: 이 멘트를 클릭하는 사람이 누구인가
   - **클릭 이유**: 그 타깃이 이 멘트를 보고 클릭하는 이유는 무엇인가
   - **심리**: 그 클릭 뒤에 있는 심리는 무엇인가
   - **도입부에서 충족되는 기대**: 클릭하고 들어와 본문 첫 도입부에서 충족되는 기대감이 무엇인가
3. 분석 내용을 반영해 **썸네일 배경 이미지 생성을 요청할 프롬프트**를 작성한다 (스타일·색은 design.md §2-4 썸네일 모드를 따름. 텍스트 금지·인물 금지·로고는 claude.png 참조 — 위 🔴 규칙).
4. 멱등: 이미 '썸네일 생성 프롬프트' 섹션이 있으면 교체한다.

**대본에 '썸네일' 파트가 없으면**: `01_대본/기획메모.md`의 5필드에 '썸네일 멘트'가 있는지 확인한다(대본 초안 경로에 따라 멘트가 대본이 아니라 기획메모에 들어오는 경우가 있다) — 있으면 그 멘트로 위 절차를 그대로 진행. 둘 다 없을 때만 분석·프롬프트 없이 아래 폴백 한 줄만 넣고 그냥 진행한다(차단 금지).

붙이는 형식:

```markdown

---

## 썸네일 생성 프롬프트

**썸네일 멘트**: "[대본 '썸네일' 파트의 메인 멘트]"

**클릭 분석**
- 타깃: [누가 클릭하는가]
- 클릭 이유: [멘트의 무엇이 클릭을 만드는가]
- 심리: [클릭 뒤의 심리]
- 도입부에서 충족되는 기대: [본문 도입부가 채워주는 기대감]

**프롬프트** (썸네일 배경 이미지용 — 텍스트·인물 없음)

[위 분석을 반영한 배경 이미지 생성 요청문 — 타깃의 심리를 자극하는 구도/오브젝트/분위기 + 멘트가 얹힐 여백(위치·명암) 지시 + "텍스트/글자/사람 넣지 말 것" 명시. 클로드 로고 등장 시 claude.png를 열어 확인한 실제 형태 묘사를 포함]
```

('썸네일' 파트가 없을 때의 폴백 형식 — 섹션 제목 아래 딱 한 줄: `썸네일 멘트 없음`)

## 레퍼런스 모션 문법 분석 (선택 — 새 연출 스타일을 잡을 때)

잘 만든 레퍼런스 영상은 "좋은 느낌"으로 보지 않고 수치로 해부한다 — 컷 길이·전환 지속(ms)·카메라 진입 시점·UI/텍스트 등장 순서가 그 영상의 **모션 문법**이다. 해부는 결정론 스크립트가, 정성 기입(전환 유형·카메라)은 사람/AI가 contact sheet를 보고 한다.

```bash
python scripts/analyze_motion.py "레퍼런스.mp4"               # scene 감지 → 구간 표 + contact sheet + 모션문법.md
python scripts/analyze_motion.py "레퍼런스.mp4" --scene 0.2   # 컷이 덜 잡히면 문턱 하향 (과하면 상향)
```

- 산출: `모션문법_<이름>/` — `cuts/`(구간별 대표 프레임) + `contact_sheet.jpg`(타일 전경) + `모션문법.md`(실측 구간 표 + 정성 기입란)
- 부드러운 전환 영상(페이드·스태거·흰 배경 슬라이드)은 scene 감지가 원리적으로 안 잡힌다 → 고정 간격 샘플링(`--interval`, 기본 2s)으로 **자동 폴백**한다.
- **자원 가드**: 30분 초과 영상은 중단(fail-loud — 발췌 후 분석 안내, `--force`로 강행) · 구간 수 상한 `--max-frames`(기본 120 — interval 모드는 간격 자동 확대, scene 모드는 문턱 조정 안내 후 중단). scene 감지는 전체 디코드라 실측 ~21배속(1440p) — 레퍼런스는 짧은 발췌가 정석이다.
- 분석 결과는 design.md §4 **장면 문법**(preset + duration + params + transition + camera)으로 번역해 preset 등재·조정에 쓴다. 매 영상 필수 아님 — 새 연출 톤을 잡거나 레퍼런스 스타일을 이식할 때만.

## 문제 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| Whisper 인증 실패 | .env 미설정 | `.env`에 `OPENAI_API_KEY` 확인 |
| Whisper `billing_not_active` | OpenAI 계정 빌링 비활성 | 로컬 openai-whisper(small) 폴백 (Step 2 참조) — 사용자에게 빌링 활성화 안내 |
| 캡처가 ~5배속/슬라이드 어긋남 | 구버전 HTML — seek 없이 rAF 시계로 진행 | 최신 템플릿의 캡처 블록(`__capture.seek`) 반영 후 재캡처 |
| frames 캡처 중단/워치독 반복 발동 | 무손상(정적) 프레임에서 beginFrame 데드락 — damage 토글 없는 구버전 스크립트 | 최신 `capture_slides.py`(픽셀 damage 토글 내장) 사용. 진단: `_capture_segs/seg_NNN.tryN.log` 자식 로그 확인 |
| python3 없음 (Windows) | 별칭 부재 | `python` 또는 `py -3` 사용 |
| 자막 타임코드가 어긋남 | 음성 파일이 교체됨 (트림본 재생성 포함) | 새 음성으로 재전사 (transcript.json 갱신) — 트림본이 바뀌면 transcript부터 전부 무효 |
| 무음 컷이 과함/부족 | 문턱(-35dB)이 녹음 환경과 안 맞음 | `--analyze` 스윕으로 `--noise` 조정 → `.trim` 재생성 → **재전사부터 다시** |
| 트림했는데 큰 갭이 남음 | 숨소리가 문턱을 넘어 무음 런이 쪼개짐(언더컷) | `--verify`로 위치 확인, 다음 영상에서 `--noise`를 -30 방향으로 조정 검토 |
| 같은 고유명사 오인식이 영상마다 재발 | 교정사전 미적용 또는 미등재 | `apply_corrections.py` 실행(Step 3a-2) + 문맥 무관 항목이면 `레퍼런스/교정사전.json`에 수확 |
| 슬라이드가 자막에 가림 | 하단 배치 | 자막 안전 영역(230px) 밖으로 — 보일러플레이트 패딩 유지 |
| 폰트가 깨져 보임 | 오프라인 | Pretendard CDN 연결 필요 (인터넷 연결 후 캡처) |
| 차트가 안 그려짐 | --circ/--off 계산 오류 | 도넛: 둘레=2πr, off=둘레×(1-비율) 재계산 |
| 캡처: 검정 커버 미검출 (realtime 모드) | HTML이 구버전 보일러플레이트 (?capture=1 미지원) | 최신 템플릿의 캡처 모드 블록을 HTML에 반영 후 frames 모드로 재캡처 |
| 조립 스크립트 중단 | CapCut 실행 중 | CapCut 완전 종료 후 재실행 |
| 드래프트가 CapCut에 안 보임/깨짐 | CapCut 업데이트로 드래프트 암호화 | 수동 조합 폴백 + 비암호화 버전으로 복원, 자동 업데이트 OFF |
