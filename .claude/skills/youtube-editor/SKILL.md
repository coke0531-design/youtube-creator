## 🔴 하지 않는 것

- **배속 변환 금지(오디오)** — 모든 타임코드는 트림본 오디오 시간 그대로 쓴다. 예외는 실사 소스의 **재생 속도**(§4-4, 0.6~1.5) 하나뿐이고, 오디오·자막·비트 타임코드는 여전히 불변.
- **kit.js 수정 금지** — 작업 폴더의 `kit.js`는 `템플릿/film/kit.js`를 그대로 복사한 것이어야 한다(`scripts/film/kit_check.py`가 md5로 검사). 버그는 필름·`kit_ext.js` 안에서 우회하고 기록한다. 킷 자체를 고치려면 정본 템플릿을 고치고 golden을 다시 만든다(킷-규격.md).
- **가짜 UI·출처 없는 숫자 금지** — 실제 제품 화면을 흉내 낸 버튼·메뉴, 대본에 없는 수치·문장을 그리지 않는다(§4-1).
- **CapCut 드래프트는 기본 산출물이 아니다** — 명시 요청 시에만(레거시 절 참조).
- Remotion/Node 빌드 불필요 — 필름은 브라우저에서 바로 열린다.

## 🔒 싱크 계약 (3자료 동기화 원칙)

완성본 = [음성 + 자막 + 필름 캡처]를 `mux.py`가 합친 것이다. 3자료는 **동일 타임베이스(t=0 = 트림본 음성 시작)** 를 공유한다:

| 자료 | t=0 | 타이밍 출처 |
|------|-----|------------|
| 음성 (`02_음성/`) | 트림본(`.trim.m4a`/`narration.m4a`) 시작 | 트림본 그대로 — 배속 없음. 유일한 오디오 편집 = Step 1.5 결정론 무음 컷 |
| 자막 (`full.srt`) | 음성과 동일 | `transcript.json` (STT 실측) |
| 필름 (`film_<막>.html`) | 막 시작 = `FILM.offset`(원본 초) | 비트 = `beats.json`(transcript 실측). 막 안의 t는 0부터, 원본 초 = t + offset |

- **워크플로우는 녹음이 먼저다**: 음성 → 무음 컷(Step 1.5) → STT → 자막 → 비트 → 필름 순. 화면 타이밍은 대본 추정이 아니라 **실제 발화** 기준이다.
- 필름은 **시간의 순수 함수** `seek(t)`로 그린다 — `capture.py`가 프레임마다 `seek(t)`를 불러 찍으므로 mp4 프레임 0 = 막 시작 초가 구조적으로 보장된다. 막 캡처를 `join_acts.py`로 이으면 전체 길이 = 오디오 길이.
- 음성 없이 요청받으면: BRIEF·DIRECTION 초안까지만 쓰고, 비트·필름·캡처는 녹음 후 확정한다고 안내한다.

## 결과물 폴더 저장 규약

모든 산출물은 `결과물/YYYY-MM-DD_<주제-슬러그>/`에 저장한다 (구조는 CLAUDE.md·`결과물/README.md` 참조).

1. 작업 시작 시 해당 작업 폴더가 있는지 확인 — 없으면 구조 생성 + `작업정보.md` 작성
2. 산출물이 생길 때마다 `작업정보.md`의 산출물 체크리스트와 상태를 갱신
3. 필름이 쓰는 파일(kit.js·kit_ext.js·live.js·실사프레임/·로고)은 `04_영상소스/` 안에 함께 저장 (상대경로 참조)

**외부 기초 자료 규칙 (산출 위치는 결과물/ 고정 — 2026-07-15 사용자 결정)** — 사용자가 자기 프로젝트 폴더(예: `MY_Ian/1. Project/풀링_011/`)에 기초 자료(`대본/` + `녹음본/` + 선택 `영상 소스/`)를 준비해 지정해도, 그 폴더에 산출하지 않는다. **`결과물/YYYY-MM-DD_<주제-슬러그>/` 작업 폴더를 새로 만들고 기초 자료를 복사해 온 뒤 모든 산출물을 그 안에 만든다**: 대본 → `01_대본/`, 녹음본 → `02_음성/`(사본+트림본+narration.m4a), 영상 소스 → `영상 소스/`(실사 원본). 외부 기초 자료 원본은 읽기만 하고 절대 수정하지 않는다 — '영상 요약'·'썸네일 생성 프롬프트' 섹션 append(Step 9)도 **작업 폴더의 대본 사본에만** 한다.

### Step 0.5: 기획 브리프 (BRIEF.md — 의도 계층, 2026-08-27 신설)

### Step 1.4: 녹음 품질 게이트 (결정론 — 트림 전에 반드시)

`python scripts/check_audio.py 02_음성/` — 트루피크·클리핑 흔적·라우드니스를 수치로 판정한다. **경고가 있으면 트림·STT로 넘어가기 전에 사용자에게 알린다**(재녹음 권고: 입력 게인 -6~-10dB, 피크 -6 dBFS 목표). 근거: 2026-08-17 풀링012·013 실측 — "녹음이 깨지는" 원인은 파이프라인이 아니라 **녹음 원본의 입력 게인 과대**(트루피크 -0.1 dBTP, 0dB 근접 런 수십 회)였고 trim·concat·final은 원본을 그대로 보존했다(라우드니스 동일, 프레임 드롭 0, SSIM 0.995+, A/V 드리프트 0.03s). 재녹음이 불가하면 완성본 합성의 loudnorm(`scripts/film/mux.py`, TP −1.5 — 레거시 render_final.py는 −1 dBTP 리미터)이 재생 오버슈트만 줄인다 — 잘린 파형은 복원 못 한다.

### Step 1.5: 무음 컷 (결정론)

긴 무음(≥1.0s)을 양끝 0.3s만 남기고 0.6s로 압축한다 — 목적은 러닝타임 단축이 아니라 **시청 템포 체감**(늘어짐 제거). 판정·컷·가드는 전부 `scripts/trim_silence.py`가 결정론적으로 수행한다(AI 귀대중 금지).

```bash
python scripts/trim_silence.py "결과물/<작업>/02_음성/녹음-1.m4a" "결과물/<작업>/02_음성/녹음-2.m4a"
# 파일별 <이름>.trim.m4a 생성 + 컷 리포트 + 03_자막/silence_cut_plan.json(컷 플랜·src↔dst 매핑)
python scripts/trim_silence.py "결과물/<작업>/02_음성/녹음-1.m4a" --analyze   # 컷 없이 문턱 스윕(캘리브레이션)
```

- **반드시 Step 2(전사) 이전에** 실행한다. 트림본을 전사해야 자막·비트·필름·캡처가 트림본 타임베이스에서 파생된다. 이미 만들어진 SRT/타임라인이 있는 상태에서 오디오만 다시 트림하면 싱크가 깨진다 → 그 경우 **재전사부터 전부 다시**.
- 기본 파라미터: `--min-gap 1.0`(무음 판정) / `--pad 0.3`(양끝 보존) / `--noise -35`(dB 문턱). **비파괴** — 원본은 그대로, 이후 파이프라인의 정본은 `.trim.m4a`. 컷 0건이어도 스트림 복사로 `.trim.m4a`를 만들어 하류 입력을 균일화한다.
- **검수: 리포트만 출력하고 자동 진행**(파라미터 검증 완료 — 2026-07-08 실녹음 1편 11파일 테스트 통과). 컷 리포트(컷 개수·삭감 초·최장 컷·타임스탬프)를 출력한 뒤 미리듣기 확인 없이 Step 2로 진행한다. 단, 삭감률이 상한(20%)에 걸려 스크립트가 중단되면 사용자에게 알리고 `--analyze`로 문턱을 재조정한다.
- 알려진 트레이드오프: ① 강조용 긴 뜸도 0.6s로 평탄화 — 컷 리포트의 타임스탬프로 위치를 안내하고 필요 시 CapCut 검수에서 되살린다(원본 보존). ② 숨소리가 문턱을 넘으면 컷이 누락되는 방향(언더컷)으로 실패한다 — 말이 잘리는 방향이 아니며, Step 2 후 `--verify`(아래)로 관측한다.

### Step 2: Whisper 전사

`OPENAI_API_KEY`는 `.env`에서 읽는다. (Windows: `python3` 대신 `python`/`py -3`) **전사 대상은 항상 트림본(`.trim.m4a`)이다 — 원본 전사 금지.**

```bash
curl https://api.openai.com/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F file="@결과물/<작업>/02_음성/녹음-1.trim.m4a" \
  -F model="whisper-1" \
  -F response_format="verbose_json" \
  -F "timestamp_granularities[]=word" \
  -o "결과물/<작업>/03_자막/transcript.json"
```

`transcript.json`(단어 타임스탬프 원본)은 쇼츠 컷 계산에도 재사용하므로 반드시 보존한다.

- **전사 직후 읽기 뷰 생성**: `python scripts/pack_transcript.py "결과물/<작업>"` → `03_자막/transcript_packed.md`(구 단위, 무음 갭 ≥0.4s는 `✂` 컷 후보 표시, 파일 경계 표시). 이후 단계(비트 표·DIRECTION 장치 자리·쇼츠 컷 선정)에서 발화 흐름·갭을 볼 때는 transcript.json 원문 대신 이 파일을 먼저 읽는다 — 시각 실측은 여전히 transcript.json 단어 타임스탬프가 정본이다.

- **API 실패 시 로컬 폴백**: `billing_not_active` 등으로 API를 못 쓰면 로컬 `openai-whisper`(pip, small 모델)로 전사한다. ffmpeg은 `imageio_ffmpeg.get_ffmpeg_exe()`를 `ffmpeg.exe`로 복사해 PATH에 넣으면 된다. 타임코드는 실측이므로 싱크 품질은 동일하고, 텍스트 오인식은 Step 3에서 대본 대조로 보정된다.
- **녹음이 여러 파일이면**: 트림본별로 전사한 뒤 누적 오프셋(앞 트림본들의 디코드 길이 합)을 더해 단일 타임베이스로 병합한다. transcript.json에 `files`(오프셋 목록)를 기록하고, ffmpeg concat(코덱 복사)으로 **트림본들의** `02_음성/narration.m4a` 단일 파일도 만들어 둔다 (Step 8 mux.py 입력). 파일별 전사 유지 = whisper API 25MB 제한 회피(트림으로 파일이 더 작아진다).
- **전사 직후 언더컷 관측(report-only)**: 트림이 정상이면 단어 갭은 ≈0.6s 이하여야 한다. 큰 갭이 남았으면 숨소리가 문턱을 넘어 무음 런이 쪼개진 것 — 다음 영상에서 `--noise` 조정 근거로만 쓴다(게이트 아님).

  ```bash
  python scripts/trim_silence.py --verify "결과물/<작업>/03_자막/transcript.json"
  ```

### Step 3: SRT 생성 (보정 규칙) + 16자 강제

**3a. AI가 transcript.json을 직접 분석해 SRT를 작성한다 (의미 보정만):**

- **자연스러운 구/문장 단위로 묶는다** — 단어 단위 ❌. **글자수(16자)를 손으로 맞추려 하지 마라.** 분할은 3b 스크립트가 한다.
- **타임코드는 원본 오디오 시간 그대로** (배속 변환 없음). **transcript.json은 불변** — 아래 교정·보정은 전부 full.srt에만 (Whisper 원본은 쇼츠 컷 계산에 재사용).

**3a-2. 교정 사전을 기계 적용한다 (반복 오인식은 프롬프트가 아니라 사전이 잡는다 — 16자 캡과 같은 구조적 강제):**

```bash
python scripts/apply_corrections.py "결과물/<작업>/03_자막/full.srt"   # 레퍼런스/교정사전.json 치환 + 적용 리포트
```

- 텍스트만 치환하고 순번·타임코드 라인은 건드리지 않는다(싱크 불변). 반드시 **3b(16자 분할) 이전**에 — 치환으로 컷이 16자를 넘을 수 있고, 그 분할은 3b가 책임진다.
- **AI는 사전 밖 오류만 대본 대조로 보정**: 잘못 분리·오인식된 단어 수정 (예: "1호는" → "이론은"), 분리 단어 합치기 ("보도" + "자료를" → "보도자료를")
- **반복 관측되지만 사전에서 제외된 오인식 — 매번 여기서 확인**: "구동료"→"구독료", "일대일"→"1대1", "이한에게"→"이안에게", "채 지피티"→"챗GPT", "재미나이"→"제미나이", "울트라 코드"→"울트라코드" (substring 오탐 우려로 사전 제외 결정 2026-07-06 — 대본 대조로 확인 후 수정)
- **수확(등재)**: 보정 중 새로 발견한 오인식 중 **어떤 문맥에서도 치환이 항상 옳은 것만** `레퍼런스/교정사전.json`의 `replace`에 추가한다 — 다음 영상부터 기계가 잡는다. 판단 기준: 오인식 문자열이 한국어에서 다른 의미로 성립할 가능성이 조금이라도 있으면(인명·복합어·의존명사 조합 등) **등재하지 말고 위 주의 목록에 추가**한다(매 영상 AI 보정 — 2026-07-06 사용자 결정). 🔴 동음이의·문맥 의존 교정("다쳐서"→"다 차서", "지었다고"→"지녔다고" 류)은 **등재 금지**(다른 영상을 오염시킨다) — 해당 영상 한정 AI 보정으로만.

**3b. 16자 하드 캡을 스크립트로 강제한다 (프롬프트 아님 — 구조적 강제):**

```bash
python scripts/split_captions.py "결과물/<작업>/03_자막/full.srt"   # 16자 초과 컷을 어절 경계로 분할(.raw.srt 백업)
python scripts/split_captions.py "결과물/<작업>/03_자막/full.srt" --check   # 검증: 초과 컷 0 확인
```

- 한 컷 ≤16자(공백 포함)는 타이포 제약이라 LLM이 100+컷 중 일부를 반드시 어긴다 → **결정론적 스크립트가 보장**한다. AI는 자연스러운 구로만 묶고, 16자 분할은 스크립트에 맡긴다.
- 분할 컷의 시간은 **원래 컷 구간 안에서** 글자수 비례 배분 → 음성·비트·필름 싱크 불변(자막 컷 수만 늘어남).
- 🔴 `mux.py`(Step 8)는 SRT를 **그대로 번인**한다 — 3b `--check` 통과가 완성본 16자의 유일한 보장이다. (레거시 `assemble_capcut.py`는 임포트 직전 같은 강제를 멱등으로 한 번 더 돌린다.) 규격·근거: [자막-안전영역.md](자막-안전영역.md).

분할 후 SRT 예시 (`자, 이렇게 명령해 놓고 잠깐 밥 먹고 오면?` → 2컷):

```srt

자, 이렇게 명령해 놓고 잠깐

2
00:00:03,967 --> 00:00:05,200
밥 먹고 오면?
```

### Step 4: 비트 표 + 연출 브리프 (DIRECTION.md — 연출 계층, v3.2)

대본에서 필름으로 직행하지 않는다. 먼저 비트 표를 뽑고, **"이 영상을 어떻게 보여줄까"**를 브리프 한 장으로 고정한다. 명령은 워크스페이스 루트에서 실행한다(`W="결과물/<작업>"`).

```bash
python scripts/film/segment.py --src "$W" --out "$W" --beats-only   # 03_자막/beats.json (음성·transcript·full.srt 해시 불변)
```

- 비트 = transcript segment(없으면 `full.srt` 병합, 그것도 없으면 words 갭 분할). 긴 녹음의 일부만 만들 때는 `--start S --end E --out <새 폴더>`(음성·transcript·SRT까지 잘라 재기준).
- `04_영상소스/DIRECTION.md`를 [연출-브리프.md](연출-브리프.md)의 6블록으로 **전부** 채운다. 빈 블록이 있으면 Step 5로 가지 않는다.
  1. `<입력>` 나레이션 길이·비트 수, 대본의 숫자·비교·절차·실패담·지침 목록(장치가 붙을 자리), 화면에 보여줄 실물 이름, **실물 소스 표**(Step 4.5)
  2. `<방향>` 분야 + 스타일(P1 기본, 조작·파일·구조 비트는 카드 줌으로 P2 — [스타일팩.md](스타일팩.md)) + 팔레트(design.md §4-A) + 글꼴 + 화면당 글자 상한 + 주인공 표(객체 연속성)
  3. `<구조>` 막 표(막 1개 = 필름 1개, 6~8분 본편이면 막 3~5개) + **핸드오프 표**(막 경계 시각과 화면 상태) + 막별 뼈대 + 수미상관 + 장치([장치사전.md](장치사전.md)에서 고르고 붙는 비트 번호) + 홀드 선언
  4. `<빌드>` 빌드 계약(§4) + 킷·실사 규칙 + 이 영상만의 추가 규칙
  5. `<금지>` 공통 금지(§5) + 이 영상만의 금지
  6. `<시작>` "코드를 쓰기 전에 비트 표를 먼저 제출하라" + 킷 담당 → 막 담당 순서
- 비트 성격 5종(8역할 type 대체): 주장 / 조작 / 비교 / 실패·복구 / 검증. 비트 표에 하나씩 붙인다. 팩은 성격으로 정한다(조작·파일·구조 = P2, 나머지 = P1).
- BRIEF.md(Step 0.5)와 어긋나는 연출이 필요하면 BRIEF를 고치고 고쳤다는 사실을 남긴다. DIRECTION은 "무엇을 말할지"가 아니라 "어떻게 보여줄지"만 다룬다.
- 오프닝 콜라주는 **선택**이다(오너 결정 9/29). 기본은 **첫 프레임 = 썸네일**(캐릭터 + 핵심 요소가 t=0에 이미 있다).

### Step 4.5: 실사 소스 준비 (`영상 소스/`가 있을 때 — 구 오버레이 인코딩 대체)

2. **프레임 추출** — 30fps JPEG 시퀀스. 카드 안 창 크기에 맞춰 줄인다(1422×800이면 충분).
   ```bash

   ```

3. **실물 소스 표** — DIRECTION `<입력>`에 파일 · 규격 · 내용 · 대사 구간(비트 #) · 카드 안/창 · **rate**(= 클립 프레임 수 ÷ (대사 초 × 30), 0.6~1.5).
4. **로더** — `템플릿/film/live.js`를 `04_영상소스/live.js`로 복사한다(Image LRU 60, async seek, FILM_READY 전 첫 프레임 선로드). `<video>` 요소는 쓰지 않는다.
5. 실사 프레임 폴더는 필름 옆에 있어야 필름이 동작한다(G 실측 81MB). 결과물 백업에 포함한다.

1. `BEATS_<막>.md`를 세분·확정하고 `film_<막>.html`을 쓴다 — 빌드 계약(§4). `FILM.offset` = 막 시작 초, t는 막 기준 0부터. **t=0 프레임과 마지막 프레임은 `KIT.HANDOFF` 함수를 그대로 호출**하고, 마지막 0.5초는 핸드오프 상태로 수렴한다. HUD 교체는 `마지막 프레임 − 0.3초`에 시작, 마지막 프레임 판정은 `t >= D − 1/fps`.
2. **가장 어려운 비트(숫자 비교·절차)를 먼저** 만들어 시트로 확인한 뒤 나머지를 채운다. 타이틀부터 만들지 않는다.
3. 비트 시트 2회(최대):
   ```bash
   python scripts/film/beatsheet.py "$W/04_영상소스/film_<막>.html" --beats "$W/03_자막/beats.json" --out "$W/04_영상소스/beatsheet_<막>_r1.jpg"
   ```

### Step 7: 캡처·잇기·측정 (스크립트)

```bash
# 막마다 (동시에 도는 capture.py는 1개 — 다른 막이 캡처 중이면 끝날 때까지 기다린다)
python scripts/film/capture.py "$W/04_영상소스/film_<막>.html" --out "$W/04_영상소스/capture_<막>.mp4" --verify-seek 5 --workers 2
python scripts/film/still_ratio.py "$W/04_영상소스/capture_<막>.mp4" --holds "$W/04_영상소스/capture_<막>.holds.json" --json "$W/04_영상소스/still_<막>.json"

# 전체 (메인)
python scripts/film/join_acts.py --acts "$W/04_영상소스/capture_A1.mp4" "$W/04_영상소스/capture_A2.mp4" … --out "$W/04_영상소스/capture.mp4" --json "$W/04_영상소스/seams.json"
python scripts/film/still_ratio.py "$W/04_영상소스/capture.mp4" --holds "$W/04_영상소스/capture.holds.json" --json "$W/04_영상소스/still.json"
```

- `--verify-seek`: t=0·끝 포함 N개 시각을 순방향 2회 + 새 페이지 무작위 순서로 찍어 픽셀 차 0을 확인한다(`<out>.verify.json`). 차이가 있으면 결정론 위반 → Step 6으로(타이머·transition·난수·이미지 로딩 순서가 흔한 원인). 실사 막은 실사 구간 시각을 따로 더 검사한다(`--start/--end`로 좁혀서).
- `--workers 2`: verify를 통과한 필름에만. 동시 캡처가 많으면 워커당 0.6~1.3fps로 떨어진다(G 실측) — 순차가 더 빠르다.
- **이음매**: `join_acts.py`가 막 N 마지막 프레임 vs 막 N+1 첫 프레임을 비교한다. mean ≤ 2 · max ≤ 80이면 OK(인코더 잡음, 그레인 배경 실측 mean 0.65~1.5). FAIL이면 HANDOFF 호출·HUD 교체 시각을 확인한다.
- **홀드 합치기**: 막별 `capture_<막>.holds.json`(막 기준 t)에 `FILM.offset`을 더해 `capture.holds.json` 하나로 합친다(`04_영상소스/`에서 실행).
  ```python
  import json; acts = [("A1", 0.0), ("A2", 42.8)]   # (막, FILM.offset)
  H = []
  for a, off in acts:
      try: H += [[h0 + off, h1 + off, why] for h0, h1, why in json.load(open(f"capture_{a}.holds.json", encoding="utf-8"))["holds"]]
      except FileNotFoundError: pass
  json.dump({"holds": H}, open("capture.holds.json", "w", encoding="utf-8"), ensure_ascii=False)
  ```
- **정지 비율 게이트**: 6초 창 raw 75% 초과(FAIL) **0개**, **홀드 제외 평균 ≤ 45%** 목표. 원시·홀드 제외 평균을 둘 다 기록한다. 전체 격자에서 막 기준 창에 없던 FAIL이 새로 생기면 그 막 담당에게 구간을 지정해 한 번 보강 → 재결합. 수치를 올리려고 장식·카메라 흔들기를 넣지 않는다(§4-3·§5) — 요소를 키우거나 큰 요소를 이동시킨다.

### Step 9: 대본에 '영상 요약'(영상 설명/챕터) 섹션 추가

영상 소스·자막·타임라인이 확정되면(Step 1~8 완료), `01_대본/`의 대본 파일 **맨 아래에 '영상 요약' 섹션을 덧붙인다**. 이 블록은 사용자가 업로드할 때 영상 설명·타임스탬프로 **그대로 붙여 쓴다**.

형식·스타일·분량은 레퍼런스 `D:\Workspace\MY_Ian\1. Project\풀링_011\대본\대본_1.md`의 맨 아래 **'영상 요약 (영상 설명 / 챕터)' 섹션을 그대로** 따른다 — **영상 설명 문단(2~3줄) + `챕터` 라벨 + 챕터 타임스탬프 목록**. (구 레퍼런스: 풀링_009 '콘텐츠 정리' — 같은 형식이며 제목만 다르다.)

**입력/대상**
- 대상: `01_대본/script.md` (순수 나레이션 대본 — `기획메모.md`는 대상 아님). 본문은 건드리지 않고 **끝에 섹션만 append**한다. 이미 '영상 요약' 섹션이 있으면 새로 만들지 말고 그 섹션을 교체한다(멱등). (대본 초안에 `## 영상 요약` 자리표시자(제목만 + 타임코드 미정)가 미리 들어 있는 경우도 같은 규칙 — 여기서 실측 타임코드로 교체된다.)
- 챕터 시간 출처: `03_자막/beats.json`(비트 실측 시각) + DIRECTION.md 막 표 + 대본 `## Part` 경계 (레거시 슬라이드 경로면 `타임라인.json`). **추정 금지 — 실측 타임코드만 사용**(비트 시각이 곧 완성본의 시간이다). 음성/비트가 아직 없으면(초안 모드) 이 단계는 건너뛰고 녹음·캡처 후 확정한다고 안내한다.

**챕터 만드는 법**
- 각 챕터 = 주제가 바뀌는 지점(대본 Part / DIRECTION 막·챕터 칩 전환)의 **첫 비트 `start` 시각**. 첫 챕터는 항상 `00:00`.
- 개수: 주제 전환마다 1개 — 영상 길이에 맞춰 **보통 6~10개**(10~20분 기준). 절대 시간 간격이 아니라 주제 전환을 기준으로 나누고, 너무 잘게 쪼개지 않는다. (레퍼런스는 4~5분 영상이라 5개)
- 시간 포맷: `MM:SS`(1시간 미만), 1시간 이상이면 `H:MM:SS`. 분·초는 영점 패딩(`01:38`).
- 챕터 제목: **호기심 유발형 한 줄**(클릭 유도) — 영상 제목 톤과 일관. 단조로운 목차형(예: "서론", "본론") 금지.

**영상 설명 문단**: 영상이 무엇을 다루는지 2~3줄, 시청자가 얻을 가치로 끝맺음(레퍼런스: "…확실히 정리되실 겁니다."). 분량도 레퍼런스와 비슷하게 짧게.

**고정 해시태그 (섹션 최상단, 변경 금지 — 2026-07-15 사용자 지정)**: 섹션 제목 바로 아래 첫 줄에 아래 텍스트를 **한 글자도 바꾸지 않고 그대로** 넣는다. 주제·영상 내용과 무관하게 항상 이 네 개다:

```
#클로드 #클로드코드 #claudecode사용법 #클로드코드활용
```

대본 파일 끝에 붙이는 형식(레퍼런스 '콘텐츠 정리' 그대로, 제목만 '영상 요약' + 고정 해시태그 첫 줄):

```markdown
챕터
```

(레퍼런스 실제 챕터 예시 — 울트라코드 편: `00:00 바이브 코딩 판을 바꾼 클로드 신기능, '울트라 코드'` / `01:38 클로드코드 없이도 가능, 울트라 코드 적용법 완전 가이드` / `02:18 … AI 에이전트 군단 활용법` / `03:00 혼자서 2~3인분, … '바이브 워킹'` / `03:47 무조건 쓰면 손해, … 2가지 함정`.)

### Step 9-2: 대본에 '썸네일 생성 프롬프트' 섹션 추가

대본이 **'썸네일' 파트 + '본문' 파트**로 나뉘어 오는 경우, '영상 요약' 섹션 뒤에 **'썸네일 생성 프롬프트' 섹션을 하나 더 append**한다. 사용자가 썸네일 배경 이미지를 직접 만들 때 이 섹션을 시드로 쓴다(이미지 생성은 사용자 몫 — 이 워크스페이스는 프롬프트까지만).

🔴 **이 단계의 산출물은 '프롬프트 텍스트'뿐이다 — 이미지 생성 호출은 하지 않는다 (2026-07-15 사용자 결정)**. 프롬프트가 묘사하는 대상은 '썸네일 배경 이미지':
- **텍스트 없음** — 멘트는 정해져 있고 사용자가 직접 얹는다. 프롬프트에 "텍스트/글자 넣지 마라"를 명시하고, 멘트가 얹힐 영역의 여백/명암 확보를 지시한다.
- **인물 활용 금지** — 사람 얼굴/신체를 배경에 넣지 않는다.
- **클로드 로고가 필요하면** 모양 참고 원본은 `레퍼런스/로고/claude.png`다 — 프롬프트를 쓰기 전에 이 파일을 **실제로 열어 보고**, 로고의 형태를 프롬프트 안에 정확히 묘사한다.

**절차**
1. 대본 '썸네일' 파트에서 **썸네일 메인 멘트**를 확인한다.
2. 멘트를 클릭 관점에서 분석한다 (4항목 — 전부 본문 도입부와 대조해 근거 있게):
   - **타깃**: 이 멘트를 클릭하는 사람이 누구인가
   - **클릭 이유**: 그 타깃이 이 멘트를 보고 클릭하는 이유는 무엇인가
   - **심리**: 그 클릭 뒤에 있는 심리는 무엇인가
   - **도입부에서 충족되는 기대**: 클릭하고 들어와 본문 첫 도입부에서 충족되는 기대감이 무엇인가
3. 분석 내용을 반영해 **썸네일 배경 이미지 생성을 요청할 프롬프트**를 작성한다 (스타일·색은 design.md §2-4 썸네일 모드를 따름. 텍스트 금지·인물 금지·로고는 claude.png 참조 — 위 🔴 규칙).
4. 멱등: 이미 '썸네일 생성 프롬프트' 섹션이 있으면 교체한다.

**대본에 '썸네일' 파트가 없으면**: `01_대본/기획메모.md`의 5필드에 '썸네일 멘트'가 있는지 확인한다(대본 초안 경로에 따라 멘트가 대본이 아니라 기획메모에 들어오는 경우가 있다) — 있으면 그 멘트로 위 절차를 그대로 진행. 둘 다 없을 때만 분석·프롬프트 없이 아래 폴백 한 줄만 넣고 그냥 진행한다(차단 금지).

붙이는 형식:

```markdown

---

## 썸네일 생성 프롬프트

**썸네일 멘트**: "[대본 '썸네일' 파트의 메인 멘트]"

**클릭 분석**
- 타깃: [누가 클릭하는가]
- 클릭 이유: [멘트의 무엇이 클릭을 만드는가]
- 심리: [클릭 뒤의 심리]
- 도입부에서 충족되는 기대: [본문 도입부가 채워주는 기대감]

**프롬프트** (썸네일 배경 이미지용 — 텍스트·인물 없음)

[위 분석을 반영한 배경 이미지 생성 요청문 — 타깃의 심리를 자극하는 구도/오브젝트/분위기 + 멘트가 얹힐 여백(위치·명암) 지시 + "텍스트/글자/사람 넣지 말 것" 명시. 클로드 로고 등장 시 claude.png를 열어 확인한 실제 형태 묘사를 포함]
```

('썸네일' 파트가 없을 때의 폴백 형식 — 섹션 제목 아래 딱 한 줄: `썸네일 멘트 없음`)

## 필름 규범 (§4~§6 — DIRECTION·킷·막 담당 공통)

### §4. 빌드 계약 (막 필름 HTML)

```
window.FILM = { duration: <막 길이 초>, width: 1920, height: 1080, fps: 30,
                offset: <막 시작 원본 초>,
                holds: [[t0, t1, "이유"], ...] }   // BEATS 홀드 열과 같은 목록(막 기준 t, 선언 없으면 빈 배열)
window.seek(t)     // t초의 화면을 그린다. 같은 t → 같은 픽셀. 상태를 프레임 사이에 들고 다니지 않는다. Promise를 돌려줘도 된다(capture가 await)
window.FILM_READY  // 폰트(+실사 첫 프레임) 로드 뒤 true
```
- `FILM.holds`는 BEATS 홀드 열과 1:1(비트 시트 검수 때 대조). capture.py가 `<out>.holds.json`으로 뽑아 still_ratio에 넘긴다.
- CSS transition·animation·setTimeout·requestAnimationFrame·Math.random·`<video>` 금지(난수가 필요하면 시드 고정 함수).
- 스프링·이징은 닫힌 식. GSAP를 쓰면 `tl.paused(true)` + `tl.totalTime(t)`만.
- 자막은 그리지 않는다(mux 번인). 하단 200px(y > 880)은 비운다. 카드 안 좌표도 y > 880·좌상단 y < 130 비움.
- 텍스트는 한글, 고유명사만 영어. 글꼴 Pretendard 1종(굵기 3단). 네트워크 없음(폰트는 로컬 또는 system-ui).
- 첫 프레임(t=0)에 이미 그림이 있다(흰 화면·빈 종이로 시작 금지). 영상 첫 막의 t=0 = 썸네일.
- 마지막 1초는 정지해도 된다(엔드카드).
- `kit.js`는 정본 사본(수정 금지), 영상 전용은 `kit_ext.js`. 필름이 `character(`를 직접 정의하거나 `STAR` 배열을 재정의하지 않는다(kit_check가 잡는다).
- 화면 숫자 옆에 주석으로 출처(`// 출처: 비트 #n`).

### §4-1. 설명 영상 전용 규칙

- **읽기 홀드는 정당한 상태다.** 비교표·명령어·프롬프트 문장은 읽을 시간만큼 멈춘다(짧은 라벨 2초, 한 줄 문장 3초). 정지 비율 수치보다 우선한다. BEATS에 `홀드`로 선언한다 — 선언 없는 정지는 죽은 시간이다.
- **객체 연속성.** 주인공(캐릭터·토큰·HUD)과 반복 등장 객체는 ID·형태·위치를 한 편 안에서 유지한다. 막 경계에서 새 룩·새 주인공 금지.
- **가짜 UI 금지.** 실제 제품 화면을 흉내 낸 버튼·메뉴 금지. 대본이 보여 주라는 메뉴·명령 **이름**만 라벨로 허용하고, 확인 안 된 것은 추상 도형으로 그린다. 실제 화면이 필요하면 실사 소스(§4-4).
- **숫자는 출처가 있다.** 화면 수치는 대본 또는 `<입력>` 출처 목록에 있어야 한다. 단위를 뺀 큰 숫자 금지. 대본에 없는 문장(예: 프롬프트 원문)을 창작하지 않는다 — 빈 줄 + 라벨로 대신한다.
- **그리는 과정이 설명이다.** 도식은 페이드 인이 아니라 "만들어진다"(선이 그어지고, 칸이 채워지고, 도장이 찍힌다). 조립 순서 = 이해 순서.
- **컷은 쌍으로 검수한다.** 비트 시트는 비트당 1장에 더해 컷 직전·직후 프레임을 쌍으로 본다.

### §4-2. 오픈소스에서 빌려온 규칙 (riso-windowseat MIT · anidoodle Apache-2.0)

- 가장 어려운 비트를 먼저 증명한다(숫자 비교·절차 → 나머지). (riso-windowseat)
- 결정론 검사는 역순·새 페이지까지 — capture.py `--verify-seek`가 무작위 순서·새 페이지로 찍는다. (riso verify.mjs, anidoodle gate.mjs)
- 첫 프레임이 썸네일이다. (anidoodle launch-video)
- 승인은 예산이다 — 메인 개입은 킷·비트 표 승인 1회 + 최종 판정 1회. (anidoodle 3회 상한)

### §4-3. 크기·구도·카메라 (v3.1~v3.2 실측 규칙)

- **요소 최소 크기.** 캐릭터 높이 ≥ 270px(기본 300), 토큰 지름 ≥ 200px, 핵심 숫자 ≥ 130px, 장치 본체 ≥ 화면 폭 30%, 카드 폭 ≥ 1150px, 라벨 ≥ 36px, 명령·메뉴 라벨 ≥ 44px. 움직임은 0.5초 동안 화면 폭 3%(58px) 이상 이동하거나 면적 20% 이상 변화 — 바늘·작은 체크·카운트 글자만 도는 것은 움직임이 아니다(판정식이 못 본다). 그런 비트에는 큰 요소 하나가 같이 움직인다.
- **3초 구도 규칙.** 무대(캐릭터·땅선) 장면은 3초마다 컷·큰 이동·새 요소 입장·카메라 이동 중 하나. "표정만 바뀜"은 구도 변화가 아니다.
- **컷 뼈대 선행.** 하드컷 첫 프레임에 이미 뼈대(무대·제목·HUD·도식 윤곽)가 있다(장치 21). 카드 줌 전 무대의 흰 카드 안에도 내용이 이미 작게 보인다(빈 카드 금지).
- **리듬 장치는 허용, 복창은 금지.** 단어 박자 확대·챕터 칩·컷 템포(장치 19~21)는 쓰되 화면 텍스트는 키워드 1~3어절·숫자·대비만.
- **카메라 규칙 4조(2026-09-30 오너 피드백 "줌인·줌아웃 반복이 과함").** 카메라(무대·카드 안 모두)는 ① 이동 뒤 최소 3초 유지 ② 한 이동은 줌 변화 ≥ 0.15 또는 팬 ≥ 화면 폭 15%(작은 밀기 금지) ③ 6초 안 왕복 금지 ④ 구간 길이 ÷ 이동 횟수 ≥ 4초. 카메라 이동은 비트 경계에서 설명 대상이 바뀔 때만. **정지 비율을 낮추려고 카메라를 흔들지 않는다.** 검사 = `scripts/film/cam_check.py`(Step 6).
- **카드 줌(P1↔P2).** 들어가기 `enterCard` 0.5초, 나오기 `leaveCard` 0.5초. 줌 전 무대는 `enterCard(ctx,0,…)`로 그려 픽셀 연속, 줌 중 카드 안 카메라는 항등. 컷으로 팩을 바꾸지 않는다. HUD·챕터 칩·배지는 줌을 따라 움직이지 않는다.

### §4-4. 실사 소스 규칙 (G r2 확정, 2026-09-30)

1. 실사는 항상 **카드 안 세상**: 카드 안(P2 `cardFull`) 고정 창 `WIN {x:1040, y:510, w:1316, h:740, r:32}`(카드 로컬 y 140~880, HUD 칩 아래 여백 ≥ 50px) 또는 무대 위 흰 카드 창(`inCard`, r 32). 둥근 모서리 + 잉크 테두리 4px. 각진 사각 금지. 캐릭터 무대(종이)에 실사를 직접 붙이지 않는다.
2. 카메라 줌·팬은 **창을 움직이지 않고 창 안의 그림에만** 적용(창으로 자른 뒤 확대, 그림이 창을 늘 덮도록 기준점 제한). 카메라 규칙 4조 그대로.
3. 대사 구간 = 실사가 보이는 구간. 클립 길이는 **재생 속도**로 맞춘다: rate = 클립 ÷ 대사, 0.6~1.5 허용, 보간 금지(rate < 1이면 같은 프레임이 두 번 나온다), 범위 밖이면 한계 속도 + 남는 시간 마지막 프레임 유지. 프레임 번호 = `min(N-1, floor((t - t0) * 30 * rate + 1e-6))`. 대사 구간이 끝나고 화면이 나가는 동안(팬·축소·모프)은 마지막 프레임.
4. 결정론: `<video>` 금지, JPEG 시퀀스(`04_영상소스/실사프레임/<이름>/%04d.jpg`, 30fps) + `live.js`(Image LRU 60, async seek, FILM_READY 전 첫 프레임 선로드). `capture.py --verify-seek` 필수. 못 불러온 프레임은 눈에 띄는 색으로 칠해 시트에서 잡는다.
5. 실사 위에 가짜 UI 덧그리기·앱 모양 흉내 요소 금지. 녹화는 확대·흐림 전환 없이 받는 것을 권장(필름 줌과 겹쳐 두 번 확대된다).
6. DIRECTION `<입력>` 실물 소스 표: 파일 · 규격 · 내용 · 대사 구간(비트 #) · 카드 안/창 · rate.

### §5. 공통 금지 목록

- 템플릿처럼 보이는 것: 같은 레이아웃이 3장 연속, 가운데 아이콘 하나 + 아래 한 줄
- 나레이션 통째 복창: 화면 텍스트가 말하는 문장 그대로. 키워드·숫자·대비만
- 튀는 이징(bounce·elastic), 파티클 폭발, 글로우, UI 크롬에 그라디언트
- 의미 없는 움직임: 숨쉬기 루프, 이유 없는 느린 팬, 정지 비율을 낮추려는 장식·카메라 흔들기
- 죽은 시간: 3초 이상 변화 없음(선언한 홀드·엔드카드 제외)
- 팔레트 밖 색(design.md §4-A 5색 + 회색 = 잉크 투명도만), 글꼴 2종 이상(하이스코어 보드 픽셀 폰트만 예외)
- 손그림 흔들림 선(획 떨림·스케치풍 겹선). 선은 곧게 긋고 끝만 둥글게(오너 판정 9/29)
- 전면 색 패널 러닝타임 10% 초과, P3(양피지 연표), 컷으로 팩 바꾸기
- kit.js 수정, 킷에 없는 주인공 창작, 캐릭터 표정 3종(base·focus·surprise) 초과

## 레퍼런스 모션 문법 분석 (선택 — 새 연출 스타일을 잡을 때)

잘 만든 레퍼런스 영상은 "좋은 느낌"으로 보지 않고 수치로 해부한다 — 컷 길이·전환 지속(ms)·카메라 진입 시점·UI/텍스트 등장 순서가 그 영상의 **모션 문법**이다. 해부는 결정론 스크립트가, 정성 기입(전환 유형·카메라)은 사람/AI가 contact sheet를 보고 한다.

```bash
python scripts/analyze_motion.py "레퍼런스.mp4"               # scene 감지 → 구간 표 + contact sheet + 모션문법.md
python scripts/analyze_motion.py "레퍼런스.mp4" --scene 0.2   # 컷이 덜 잡히면 문턱 하향 (과하면 상향)
```

- 산출: `모션문법_<이름>/` — `cuts/`(구간별 대표 프레임) + `contact_sheet.jpg`(타일 전경) + `모션문법.md`(실측 구간 표 + 정성 기입란)
- 자원 가드: 30분 초과 영상은 중단(`--force`로 강행) · 구간 수 상한 `--max-frames`(기본 120). 레퍼런스는 짧은 발췌가 정석이다.
- 분석 결과는 새 장치(장치사전.md) 등재·DIRECTION `<방향>` 조정에 쓴다. 매 영상 필수 아님.

## 문제 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| verify-seek FAIL | seek가 순수하지 않음(타이머·transition·난수·캐시 누락·이미지 로딩 순서) | 필름에서 원인 제거 → 재검사. 실사는 `LIVE.render`처럼 필요한 프레임을 전부 await한 뒤 동기로 그린다 |
| 이음매 FAIL(mean > 2 또는 max > 80) | 첫/끝 프레임이 HANDOFF를 그대로 호출하지 않음, HUD 교체 시각 어긋남 | `t >= D − 1/fps`에서 HANDOFF 호출, HUD 교체는 끝 − 0.3초 |
| cam_check exit 2 | CAM 배열이 숫자 리터럴이 아님(스프레드·변수) | `const CAM=[[t,x,z],…]` 숫자로 풀어 쓴다 |
| cam_check R2 위반인데 z 0.15 차이 | 부동소수 1.15−1 = 0.1499… | 0.16처럼 여유 |
| still_ratio 전체 격자에서 새 FAIL | 막 기준 창과 전체 창 격자가 다름 | 그 막 담당에게 구간 지정 보강 1회 → 재결합 |
| 캡처가 매우 느림(워커당 1fps 안팎) | 여러 막 동시 캡처 | 막 캡처는 순차, `--workers 2` |
| kit_check FAIL(md5) | kit.js를 고쳤거나 옛 사본 | 템플릿에서 다시 복사, 필요한 함수는 kit_ext.js로 |
| 한글 경로 cv2.imwrite 실패 | OpenCV 한글 경로 미지원 | `cv2.imencode` + open/write |
| Whisper 인증 실패 | .env 미설정 | `.env`에 `OPENAI_API_KEY` 확인 |
| Whisper `billing_not_active` | OpenAI 계정 빌링 비활성 | 로컬 openai-whisper(small) 폴백 (Step 2 참조) — 사용자에게 빌링 활성화 안내 |
| [레거시 슬라이드] 캡처가 ~5배속/슬라이드 어긋남 | 구버전 HTML — seek 없이 rAF 시계로 진행 | 최신 템플릿의 캡처 블록(`__capture.seek`) 반영 후 재캡처 |
| [레거시 슬라이드] frames 캡처 중단/워치독 반복 발동 | 무손상(정적) 프레임에서 beginFrame 데드락 — damage 토글 없는 구버전 스크립트 | 최신 `capture_slides.py`(픽셀 damage 토글 내장) 사용. 진단: `_capture_segs/seg_NNN.tryN.log` 자식 로그 확인 |

| 자막 타임코드가 어긋남 | 음성 파일이 교체됨 (트림본 재생성 포함) | 새 음성으로 재전사 (transcript.json 갱신) — 트림본이 바뀌면 transcript부터 전부 무효 |
