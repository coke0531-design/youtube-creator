# YouTube Shorts 소스 제작 (9:16)

본편 음성·대본에서 쇼츠 후보를 추출하고, 쇼츠별 **3종 산출물**을 만든다:

| # | 산출물 | 파일 | 설명 |
|---|--------|------|------|
| ① | 세로 소스 | `05_쇼츠/short-NN/source.html` | 9:16 슬라이드 HTML — **SLIDE_TIMELINE 내장 (쇼츠 타임라인 기준), 동기화 오토플레이 녹화** |
| ② | 자막 | `05_쇼츠/short-NN/short-NN.srt` | 쇼츠 타임라인 기준으로 재계산한 SRT |
| ③ | 동기화 데이터 | `컷지시서.md` + `타임라인.json` | 원본 오디오 컷 매핑 + CapCut 조합 (사람용 MD + 기계용 JSON — CapCut 드래프트 자동 조립의 입력) |

## 🔴 하지 않는 것

- **최종 영상 합성/내보내기(export) 금지** — 드래프트 검수·내보내기는 사용자가 CapCut에서. (capture.mp4 캡처와 드래프트 조립은 본편과 동일하게 `scripts/`로 자동)
- **배속 변환 금지** — 원본 속도(1.0x) 그대로.

## 🔒 싱크 계약

쇼츠도 [음성 컷 + 자막 + 세로 소스] 3자료가 **쇼츠 타임라인(t=0 = 첫 컷 시작)** 하나를 공유한다:

- 세로 소스에 `SLIDE_TIMELINE`(쇼츠 타임라인 기준)을 임베드 → **캡처 모드로 헤드리스 통녹화**: `python scripts/capture_slides.py <source.html> --timeline <쇼츠 타임라인.json>` (type=short → 출력 1440x2560 자동, 레이아웃은 1080x1920 기준). 수동 폴백: `A` → SPACE 화면 녹화
- `short-NN.srt`도 쇼츠 타임라인 기준으로 재계산 (오디오-컷.md 공식)
- `타임라인.json`의 `audio_cuts`가 원본 오디오 ↔ 쇼츠 타임라인 매핑을 보존 — `scripts/assemble_capcut.py`가 이대로 오디오를 컷 배치해 CapCut 드래프트를 만든다 (방식·주의사항: youtube-editor SKILL.md Step 7–8)
- 전제: 본편 `transcript.json`(STT 실측)이 있어야 한다 — **녹음/전사가 먼저**. transcript는 **무음 컷 트림본 타임베이스**(youtube-editor Step 1.5)이므로 `audio_cuts`의 src와 `audio_source`도 같은 트림본 계열(`02_음성/narration.m4a` = 트림본 concat)을 쓴다. 🔴 미트림 원본을 지정하면 컷이 조용히 어긋난다

## 디자인 원칙 — 인포그래픽 퍼스트

1. **말로 풀지 말고 그려서 보여준다** — 설명이 필요한 내용일수록 시각화가 먼저다
2. **인포그래픽 짤림 금지** — 세로 화면 안에서 차트/그래프가 절대 짤리면 안 된다
3. **한 슬라이드, 한 인포그래픽** — 하나의 시각적 메시지에 집중
4. **세로 포맷 재구성** — 16:9 가로 배치를 9:16 세로 배치로 변환
5. **텍스트의 역할은 라벨·값 표시까지** — 주인공은 항상 그림이다

### 금지 패턴

```
❌ 텍스트만으로 슬라이드 구성 (감정/전환 구간 외)
❌ 검정/다크 배경 (영상 소스는 흰색 고정)
❌ overflow: hidden으로 인포그래픽 잘라내기
❌ 16:9 슬라이드를 세로에 그대로 레터박싱
❌ 4색 외 색 사용 (보라/네온그린/골드/레드)
❌ 하단 440px(자막 영역)에 콘텐츠 배치
```

## 나레이션 분석 (필수 선행)

본편 `03_자막/transcript.json`(또는 대본)을 구간별로 훑으며 **역할 + 감정**을 함께 적는다 (감정 어휘: [감정-설계.md](감정-설계.md) §2):

```
훅        구간 — 즉시 관심을 끄는 대목            (주로 놀라움·위기감)
문제 제기 구간 — 시청자의 답답함을 건드리는 대목   (주로 공감·위기감)
해결      구간 — 방법·원리를 알려주는 대목         (주로 지식·놀라움)
증거      구간 — 수치·사례로 뒷받침하는 대목       (주로 놀라움)
행동 유도 구간 — 다음 행동을 권하는 대목           (긴박감)
군더더기  구간 — 배경 설명·반복 → 쇼츠에서 잘라낼 대상
```

### 후보 정리 절차

쇼츠 후보가 4개 이상 나오면 아래 순서로 2~3개(각 20~60초)까지 줄인다:

1. 오디오 구간이 이어져 있는 두 후보 → 하나로 합친다
2. 군더더기 비중이 40%를 넘는 후보 → 훅 구간만 남기고 점프컷
3. 주제가 겹치는 후보들 → 합쳐서 1개로 재구성 (주력 감정이 겹칠 때도 동일 — 감정-설계.md §1)
4. 독립적이고 임팩트가 있는 후보 → 그대로 유지

## 워크플로우

```
1. 입력 확인     본편 작업 폴더의 transcript.json + 대본 확인
2. 나레이션 분석  역할/감정 태깅 → 쇼츠 후보 선정 (위 후보 정리 절차)
3. 컷 구간 확정   쇼츠별 원본 오디오 구간 결정 (군더더기 구간 제외)
4. 세로 소스 제작 보일러플레이트 복사 → 9:16 슬라이드 작성 + SLIDE_TIMELINE 임베드 (쇼츠 타임라인 기준)
5. SRT 재계산    쇼츠 타임라인 기준 (오디오-컷.md 공식) → split_captions.py로 16자 강제
6. 동기화 데이터  컷지시서.md (사람용) + 타임라인.json (기계용 — audio_cuts 포함)
7. 캡처          scripts/capture_slides.py --timeline <쇼츠 타임라인.json> — 헤드리스 캡처(1440x2560)
8. 드래프트 조립  scripts/assemble_capcut.py <쇼츠 타임라인.json> — audio_cuts대로 오디오 컷 배치 (CapCut 닫은 상태)
8.5 조립 재료    scripts/stage_capcut_kit.py <쇼츠 타임라인.json> — '캡컷 조립 재료/'에 조립 파일 모음(하드링크)
9. 마무리        작업정보.md 갱신 (쇼츠 N개 추가) — 수동 오디오 컷은 자동 조립 실패 시 폴백(오디오-컷.md)
```

방식·주의사항(캡처 모드·CapCut 종료·절대경로·싱크 검증 게이트)은 youtube-editor SKILL.md Step 6.9~8.5와 동일하다.

저장 위치: `결과물/<작업>/05_쇼츠/short-01/`, `short-02/`, ...

### Step 5 — 자막 16자 강제 (본편과 동일)

쇼츠 타임라인 기준으로 SRT를 재계산한 뒤, **한 컷 ≤16자(공백 포함)를 스크립트로 강제**한다 (프롬프트 아님 — 규칙 준수는 구조가 만든다):

```bash
python scripts/split_captions.py "결과물/<작업>/05_쇼츠/short-NN/short-NN.srt"          # 16자 분할(.raw.srt 백업)
python scripts/split_captions.py "결과물/<작업>/05_쇼츠/short-NN/short-NN.srt" --check   # 검증: 초과 0
```

- 분할 컷의 시간은 **원래 컷 구간 안에서** 글자수 비례 배분 → 쇼츠 타임라인·SLIDE_TIMELINE·audio_cuts 싱크 불변(자막 컷 수만 늘어남).
- `assemble_capcut.py`도 임포트 직전 같은 강제를 멱등으로 한 번 더 돌린다 — Step을 빠뜨려도 최종 드래프트는 항상 ≤16자. 규격·근거: youtube-editor [자막-안전영역.md](../youtube-editor/자막-안전영역.md).

## 훅 퍼스트 (첫 1초)

첫 1초가 승부. **첫 슬라이드부터 시각적 임팩트** — 연출은 주력 감정에 맞춘다([감정-설계.md](감정-설계.md) §4).

| 규칙 | 설명 |
|------|------|
| 첫 슬라이드 = 임팩트 | 빅 카운터, 비교 바, 임팩트 문구가 즉시 등장 |
| `.slam` 클래스 | 훅 문구 scale slam (1.3 → 0.96 → 1) |
| 페이드인 인트로 금지 | 빈 화면으로 시작하지 않는다 |

## 슬라이드 시각화 결정 트리

```
슬라이드가 다룰 대사의 성격은?
├─ 숫자/데이터? → 빅 카운터(.big-counter) + KPI 세로 스택
├─ 비교?       → 가로 바(hbar, maxWidth 30rem) / Before-After 상하 분할(ba-stack)
├─ 비율?       → 도넛 (280px급) + 중앙 숫자
├─ 프로세스?   → 세로 스텝(vstep-list)
├─ 시간 흐름?  → 세로 타임라인
├─ 도구/기술?  → 로고 칩 + 라벨
├─ 감정/전환?  → (Fallback) 임팩트 타이포(.impact) — 쇼츠는 허용
└─ 해당 없음?  → SVG 기본 도형 + 라벨
```
