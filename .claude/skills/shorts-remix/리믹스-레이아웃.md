# 리믹스 레이아웃 — 검은띠·헤드카피·자막 규격

캔버스 1080x1920 고정. 유튜브 공식 안전영역 수치는 비공개라, 제3자 실측들의 **가장 보수적인 값**을 채택했다(근거: `레퍼런스/쇼츠-리믹스-조사-2026-08.md` §1~2). 최종 확인은 반드시 실제 폰에서.

## 구획 (y 좌표)

**기본 = 소스 재생성 모드 (2026-08-13 사용자 결정)** — 원본 영상 픽셀 대신 컷 구간용 슬라이드 소스를 새로 그려 캡처해 넣는다. 이중 자막(원본에 박힌 자막)과 16:9 슬롯이 작은 문제를 동시에 해소한다.

```
y    0 ~  200   상단 UI 회피 — 비움 (검색·뒤로가기 영역)
y  200 ~  500   헤드카피 블록 (300px)
y  500 ~ 1200   재생성 소스 (1080 x 700, 흰 배경 슬라이드)
y 1200 ~ 1460   자막 구역 (62px, ASS MarginV=590 → 하단선 y≈1330, 소스와 ≥40px 간격)
y 1460 ~ 1920   하단 UI 회피 — 비움 (460px: 채널명·설명·음원 + 우측 아이콘 열 하단)
```

폴백 = 원본 픽셀(extract) 모드: 16:9 본편을 1080x608로 y=500에 배치(재생성이 과한 일회성 작업용). 원본에 자막이 박혀 있으면 이중 자막이 생기므로 기본으로 쓰지 않는다.

- 좌우: 본편은 풀폭. 텍스트류는 좌우 80px 이상 안쪽(우측 아이콘 열 ~140px 침범 금지, 가운데 정렬이 기본이라 실질 무관).
- 상단 띠 총 500px(26%), 하단 띠 총 812px(42%) — 하단이 두꺼운 게 정상이다.

## 색

| 요소 | 값 |
|------|-----|
| 띠 배경 | `#0A0A0A` (순검정 대신 — OLED에서 영상 경계 덜 튐) |
| 헤드카피 기본 | `#ffffff` |
| 헤드카피 강조어 | `#F59E0B` (design.md 브랜드 앰버 — 조사에서는 노랑 관행이지만 브랜드 SSOT 우선) |
| 자막 | 흰색 + 검정 외곽선 3px (배경 박스 불필요 — 띠가 이미 어두움) |

## 타이포

| 요소 | 폰트 | 크기 | 제약 |
|------|------|------|------|
| 헤드카피 | Pretendard(Black/900) 계열 | 80px (2줄이면 72px 자동 축소) | ≤2줄, 줄당 ≤15자, letter-spacing −0.02em |
| 자막 | Pretendard Black | 62px | 한 컷 ≤16자 (split_captions.py 강제), 1줄 |
| 재생성 소스 내 텍스트 | design.md 규정 | 본문 40px+, 라벨 28px+ | 1080x700 기준, 가장자리 세이프 40px |
| CTA 엔드카드 | 동일 | 72px | 2초, 무음 |

- 크기 근거: 1080폭 ÷ 줄당 글자 수 역산(헤드카피 12~14자 → 77~90px, 자막 16자 → ~60px). 공개 표준 없음 — 실측 검수로 보정한다.
- CapCut 수동 폴백 시 환산: 입력값 = 목표px ÷ 0.24 (헤드카피 80px → 333, 자막 62px → 258). 모바일 CapCut 슬라이더 상한이 ~72px이라 헤드카피는 PC판 직접 입력 필요.

## 소스 처리

- remix_shorts.py가 ffprobe 실측 해상도로 목표 크기를 계산해 고정 픽셀 `scale`(lanczos)로 넘긴다 — **1930x1080 이상치 소스(풀링_005·006·008)도 왜곡 없이 결정론적으로 흡수**된다(세로가 ~604px로 살짝 짧아질 뿐).
- 원본 좌우 크롭(확대형 B안)은 기본 금지 — 슬라이드 텍스트가 잘린다. 인물 클로즈업이 필요한 소스에서만 별도 판단.
- 배속 금지(전역 규칙). 첫 프레임부터 본론 — 페이드인 인트로 금지.

## 인코딩 (remix_shorts.py 고정값)

H.264 High, yuv420p, 10Mbps급, AAC 48kHz 스테레오, 30fps, `-movflags +faststart`, 최종 1080x1920. 총길이 20~179초 밖이면 스크립트가 차단(fail-loud).
