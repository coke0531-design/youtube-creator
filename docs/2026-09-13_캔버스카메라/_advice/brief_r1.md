# astra 자문 1라운드 브리프: 레퍼런스 모션 문법 검증 + 접목 관점

## 우리 상황
- youtube-creator = 확정 대본 + 나레이션 녹음 → HTML 슬라이드(흰 배경 4색, Pretendard) → 헤드리스 캡처 → CapCut 드래프트. 모션은 CSS preset + GSAP 로컬 타임라인(`data-tl`)을 나레이션 단어 타임스탬프에 붙인다.
- 하고 싶은 것: 레퍼런스의 "캔버스 위 카드가 큐마다 하나씩 생기고, 카메라가 새 카드를 잡으러 팬/줌하다가 마지막에 전체 줌아웃" 연출과 "유령→실체 등장", "진행형 표", "제자리 바꿔치기"를 우리 시스템에 흡수. 회화 배경은 4색 원칙과 충돌하므로 채택 안 함.
- 리스크로 이미 보고 있는 것: (a) 기존 흰 배경 미니멀 무드가 흐려질 가능성 (b) 긴 정지(5~8초)가 우리 check_motion 게이트(슬라이드 6초 초과·정지 비율 75% FAIL, 50% WARN)와 충돌 (c) 카메라 확대 시 텍스트 선명도·자막 안전영역(하단 21vh) 침범 (d) 캡처가 프레임 단위 seek 방식이라 카메라 트윈이 결정론적이어야 함 (e) 새 preset이 늘면 워커(프레임 제작 위임)의 자유도가 커져 톤이 흐트러짐.

## 답해 주세요 (파일 `astra_r1.md`로 이 폴더에 저장, 한국어, 마크다운)
1. **분석 검증**: `01_레퍼런스_분석.md`의 문법 판독 중 틀렸거나 과장됐거나 빠진 것. 정지 화면으로 확인 가능한 범위에서. 특히 "카메라는 새 요소가 화면 밖에 생길 때만 움직인다", "마지막은 항상 전체 줌아웃", "유령→실체"가 정말 핵심인지, 아니면 다른 것이 더 본질인지.
2. **왜 이 연출이 먹히는가**: 시청자 인지 관점에서 이 연출이 주는 효과 3가지 이내와, 반대로 어디서 지루하거나 촌스러워질 수 있는지.
3. **접목 방식 후보 3안**: 우리 템플릿(HTML+GSAP, 프레임 단위 seek 캡처)에 넣는 방법을 3가지 다른 깊이로. 예: (i) 슬라이드 하나 안의 `.canvas` 그룹 transform만 트윈하는 최소안 (ii) 카메라 헬퍼(`cam.frame(el, zoom)` / `cam.fit()`)와 유령 등장·조립 preset을 렉시콘에 등재하는 표준안 (iii) 스토리보드 필드에 `cam` 줄을 추가하고 게이트까지 바꾸는 전면안. 각 안의 이점·비용·되돌리기 난이도.
4. **리스크 점검**: 위 (a)~(e) 외에 우리가 놓친 리스크. 특히 "기존 결과물 수준이 오히려 떨어질" 시나리오를 구체적으로.
5. **A/B 실험 설계**: 오너가 직접 보고 판단할 비교 실험을 어떻게 짜야 공정한가. 같은 대본·같은 음성으로 기존 방식 vs 새 방식을 몇 장면, 어떤 종류(비교·목록·흐름·개념)로 만들면 판단이 잘 서는지. 판단 기준 목록도.
6. **한 줄 권고**: 채택/부분 채택/기각 중 무엇을 권하며 이유.
