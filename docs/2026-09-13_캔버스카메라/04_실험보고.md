## 2. 공정성을 위해 한 것과 못 한 것

- 한 것: 같은 오디오 파일·같은 구간·같은 출력 설정(2560×1440, 30fps, crf 17). A와 B는 같은 부품 파일에서 조립(`_parts/build.py`, `buildA.py`)해 텍스트·큐가 기계적으로 같다. A의 개념 장면은 현행 preset(`.el--w-*` 무게 스태거, `.stage` 교체, draw-on)으로 따로 만들었고, 상태 A가 큐(122.35)보다 먼저 보이던 결함을 고쳐 재캡처했다.
- 못 한 것(오너가 감안할 점): ① A의 비교·목록·흐름은 B의 캔버스를 축소해 고정한 것이라, 현행 방식으로 처음부터 그렸을 때보다 글자가 작을 수 있다(고정 배율 0.67~0.86). ② B의 첫 샷에서 카드 하나가 화면 중앙에 뜬다(2차에서 흐름 카드를 키웠지만 여전히 화면 폭의 32%). 둘 다 "카메라의 효과"가 아니라 이번 레이아웃의 크기 선택 문제다. ③ 1차 결함(비교 카드별 팬·전체 축소 뒤 결론)을 2차에서 고쳤고 오너가 보는 클립은 2차다.

## 4. 구현 중 잡은 결함 (레퍼런스를 흡수할 때 반드시 겪는 것)

1. GSAP `fromTo`의 기본 `immediateRender`가 뒤 단계 트윈의 from 값을 빌드 시점에 화면에 찍어, 카드가 옅게 미리 보였다 → 요소별 첫 트윈만 즉시 렌더.
2. SVG `marker-end` 화살촉은 dash 기반 draw-on을 무시해 선보다 먼저 보였다 → 촉을 별도 path로 두고 선이 80% 그려진 뒤 나타나게.
3. 둥근 선끝(round cap)이 dashoffset 상태에서도 점으로 비쳤다 → 그리기 시작까지 opacity 0.
4. 점선은 dashoffset으로 그릴 수 없다 → 옅게 나타남으로 대체.
