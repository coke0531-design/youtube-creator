# 영상 소스 품질 개선 아키텍처 v6 (2026-08-27)

> 정본. 이 문서가 이번 개편의 결정 기록이다. 근거 원문은 세션 스크래치의 `hf-review/`(HyperFrames v0.8.16 전수 리뷰 22편 + 결정용 다이제스트 DIGEST.md)와 Threads 레퍼런스 해독 결과다.

## 0. 왜 고치는가 (오너 요청)

1. 현재 시스템은 작업의 목적, 의도, 맥락, 목표를 제대로 파악하지 못한 채 대본에서 슬라이드로 직행한다. 그래서 "맞긴 한데 수준이 낮은" 영상 소스가 나온다.
2. HyperFrames(오픈소스, HeyGen, Apache-2.0)로 만든 결과물 품질이 좋았으므로, 최신판을 전부 확인하고 합치거나 이용해서 개선한다.
3. 참고 레퍼런스: Threads @kez_works의 Vox 스타일 워크플로우(감독 + 역할 에이전트 10명 생산라인, 콜라주 룩)와 그 원류 @gasket_love의 Vox 애셋 제작법.

## 1. 진단 (품질 격차의 실제 원인)

| # | 원인 | 증거 |
|---|---|---|

| 6 | **한 컨텍스트가 전부 수행한다.** 대본 분석부터 42장 슬라이드 HTML까지 한 세션이 만들면 후반부 품질이 떨어진다. kez_works와 HF 둘 다 역할 분업(프레임당 워커 1명 + 감독 검수)으로 푼다. | kez 구조도, HF frame-packets |

## 2. 엔진 결정 (HyperFrames를 어떻게 쓰나)

3경로를 실측·코드 근거로 비교한 결과:

| 경로 | 판정 | 결정 근거 |
|---|---|---|
| (a) 본편 렌더러 전면 교체 | **기각(지금은)** | HF 렌더는 Windows에서 결정론 캡처(BeginFrame)가 코드에서 리눅스 전용으로 잠겨 스크린샷 모드로 돈다(`browserManager.ts:656`). 우리 `capture_slides.py`가 결정론 경로에서 오히려 앞선다. CapCut 드래프트 계약·2560x1440·`validate_pipeline.py` 검사 B가 전부 깨진다. 템플릿도 전면 재작성 필요. |
| (b) 히어로 인서트 렌더러 | **채택** | 콜라주와 같은 자리: `video_overlays`에 `style:"hyperframes"`로 등록, `encode_overlays.py`는 건너뛰고 `render_hf.py`가 렌더. 8초에 26~45초라 인서트 단위로 실용적. 한글+Pretendard+오디오 t=0 mux 실측 성공. |
| (c) HF 자산을 우리 캡처 루프에 인라인 | **채택(최대 수확)** | HF 2세대 컴포넌트를 GSAP paused 타임라인 그대로 `presentation.html`에 넣고 `__capture.seek(t)`에서 `tl.totalTime(t+0.001,true); tl.totalTime(t,false)`로 구동하는 방식이 실측 성공(어댑터 약 40줄). 엔진 도입 없이 seek-safe 모션 체계를 얻는다. |

핵심 함정(실측·코드 확정, 구현 시 준수):
- `tl.seek(t)` 금지. 이벤트를 억제해서 `onUpdate` 기반 아이템이 0프레임에 얼어붙는다. 반드시 `totalTime` 2호출.
- GSAP `<script>`는 컴포넌트 스크립트보다 먼저. 순서가 틀리면 에러 없이 정지 화면으로 구워진다.
- 렌더 게이트: HF `check`의 명암비 임계는 변경 불가(큰 텍스트 3:1, 작은 텍스트 4.5:1). 흰 배경 앰버 `#F59E0B` 텍스트는 2.15:1로 실패. 텍스트는 기존 규칙대로 `#D97706`(큰 텍스트), 더 작은 텍스트 강조는 `#b06f07` 검토.
- `npx hyperframes` 계열 명령은 항상 `HYPERFRAMES_SKIP_SKILLS=1 HYPERFRAMES_NO_TELEMETRY=1`과 함께. init이 홈의 에이전트 폴더 10곳에 스킬을 무단 복사한다(이번 세션에서 실측, 원복 완료).
- CLI는 실행 폴더의 `.env`를 자동 로드한다. youtube-creator 루트에서 직접 돌리지 말 것(OPENAI 키 노출).

## 3. 목표 아키텍처 (계층 5개)

```
[0] BRIEF.md (기획 브리프)        ← 신설: 목적·의도·맥락·목표를 파일로
[1] STORYBOARD.md (연출 스토리보드) ← 신설: 프레임별 역할·비트·샷 시퀀스(나레이션 단어 큐)
[2] 프레임 제작 (분업)             ← 개편: 프레임 패킷 → 워커 병렬 → 감독 조립
[3] 모션 시스템 v2                 ← 개편: GSAP seek-safe + 모션 교리 + 벡터 문법
[4] 기계 게이트                    ← 확장: 스토리보드 검사 + 모션 실측 게이트 + HF 감사기
```

### 3-0. BRIEF.md (Step 0.5 신설)

HF 의도 계층의 번역판. 대본이 이미 확정돼 오므로 "무엇을 말할까"가 아니라 **"어떻게 보여줄까"의 브리프**다.

- 위치: `결과물/<작업>/01_대본/BRIEF.md`. 한 번 쓰면 그 작업의 진실(no-repeat token). 이후 단계는 브리프 질문을 다시 하지 않는다.
- 프론트매터: `message`(이 영상이 전달할 단 하나의 결론), `audience`(누구에게, 그들이 이미 아는 것), `goal`(채널 목표: 구독·신뢰·전환 등), `angle`(concept / how-to / listicle / story 중 하나), `length`, `tone`, `visual_concept`(선택된 비주얼 텔링), `must_show`, `avoid`.
- 본문: `## 의도`(산문), `## 재료`(사용자 제공 소스), `## 메모`.
- 채움 절차: ① 기획메모.md·대본·content-oracle 리서치에서 자동 추론 ② **비주얼 텔링 피치 3~5안**(같은 대본의 다른 보여주기 방식. HF 피치 라운드 규칙: 최소 2안은 뻔하지 않은 경로, 5안 전부 제시 후 추천) ③ "오너가 말한 것"과 "추론한 것"을 분리해 제시하고 확인받는다. 오너 부재(자율) 모드면 추론 근거를 명시하고 진행.

### 3-1. STORYBOARD.md (Step 4 개편)

슬라이드 분해를 머릿속이 아니라 파일로. 프레임(슬라이드) 하나당:

```md
## Frame 07 — 두더지 잡기
- type: pain_point            # 8역할 enum (hook/pain_point/product_intro/feature_showcase/benefit_highlight/social_proof/branding/cta)
- persuasion: 비유 + 반복 강조   # 이름 붙은 설득·명료화 기법 (막연한 "설명" 금지)
- beat: 답답함→공감            # 감정 비트
- blueprint: grid-card-assemble (Adapt)  # HF 블루프린트 id 또는 compose
- route: staged-reveals        # 지속 모션 루트 5종 중 1 (구간 전체의 주인)
- vec: {axis: x, dir: -1}      # 전환 벡터 (기본 = 조류 LEFT)
- focal: 무한 반복 카드          # 이 비트의 주인공 요소
- 오디오: 01:20.3~01:27.0

Scene 1 (0.0~1.2s): "하나 고치면" 어절에 카드1 등장(weighted stagger, 무거움)
Scene 2 (1.2~3.5s): "다른 데서 터지는" 어절에 카드2 + 마커 X 드로우온
Scene 3 (3.5~6.7s): "계속 반복" 어절에 반복 화살표 self-draw → 정지 홀드(클라이맥스 전 0.4s 쉼표)
```

- 샷 시퀀스의 시각은 전부 `transcript.json` 단어 타임스탬프에서 나온다(추정 금지). 창 개수 = 나레이션 큐 개수. 첫 25%에 다 쏟는 프론트로딩 금지, 후반 50%에도 리빌.
- 문서 상단에 `## Video direction` 블록 1회: 팔레트(4색 고정), 모션 문법(power3 롱테일 기본), 조류 방향과 예약 벡터, 정지 프레임 배분, 금지 목록.
- 이 파일이 편집지시서·타임라인.json의 상류가 된다(연출 컬럼은 스토리보드에서 파생).

### 3-2. 프레임 제작 분업 (Step 5 개편)

- 감독(메인 세션)이 STORYBOARD 확정 → 프레임 패킷 생성(프레임 블록 + 해당 블루프린트 본문 + 인용 rule 본문 인라인, 48KB 상한) → **프레임 워커 병렬 디스패치**(워커 1명 = 2~3프레임, HF general-video 실측 규칙: 6프레임 이하 작업은 인라인이 더 빠르므로 분업 생략).
- 워커 출력 = `<section class="slide">` 조각 + 슬라이드 로컬 GSAP 타임라인 1개. 워커는 STORYBOARD 전체를 열지 않는다(패킷이 전부).
- 감독이 조립 → 게이트(3-4) → 캡처. 모델 규칙: 판단(스토리보드·최종 검수) = 메인, 프레임 제작 노동 = opus 위임.

### 3-3. 모션 시스템 v2 (템플릿 v2 + design.md §4 확장)

**구동 방식**: 슬라이드는 CSS 상태기계를 유지하되, 샷 시퀀스가 있는 슬라이드는 `data-tl` 표시 + 슬라이드 로컬 GSAP paused 타임라인을 갖는다. `applyEntry`/`__capture.seek(t)`가 슬라이드 로컬 시간 `local = t - slide.start`로 `tl.totalTime(local+0.001,true); tl.totalTime(local,false)`를 호출한다. GSAP 3.15.0은 로컬 벤더(`벤더/gsap.min.js`, HF 리포의 공식 배포본과 sha256 동일 확인분).

**교리 4법칙(design.md §4에 추가, HF에서 번역)**:
1. 부드러움이 통통 튐을 이긴다: 기본 이징 = power3 계열 롱테일. bounce/elastic 금지(back.out 1.4~1.7 허용은 현행 유지).
2. 리빌은 나레이션 큐에: 조각은 그 말이 나오는 순간 등장, 후반 50%에도 리빌. 프론트로딩 = FAIL.
3. 나쁜 모션보다 정지: 숨쉬기 루프·후반 슬로우 팬 금지. 모든 구간은 루트 5종(staged-reveals / camera-with-intent / sequenced-ui-life / animated-sequences / carrier-led) 중 하나가 소유. 클라이맥스 앞 0.3~0.75초 정지 쉼표.
4. 컷은 속도 일치: 내부 이음매·슬라이드 전환은 양쪽 다 움직이는 도중에, 같은 축·방향·맞춘 속도(미러 이징 power4.in/out).

**새 preset(렉시콘 등재)**:
- `스태거--무게`(weighted stagger): 앵커 60~80px·0.16~0.20s / 보통 40~50px·0.13~0.16s / 가벼움 30~48px·0.10~0.13s, 간격은 캐스케이드를 따라 감소. 수치는 1920 기준, 구현은 비율.
- `넛지 커브`(nudge curve): 그룹 재배치 3단 체인(거리 10/65/25%, 시간 20/18/62%, 램프인 power3.in → 선형 버스트 → power4.out 꼬리). 새 콘텐츠는 버스트 중에 드러낸다.
- `컷 더 커브`(슬라이드 전환 옵트인 `.slide--cut`): 부분 이동 12%(1920에서 230px), exit power4.in 0.3s + entry power4.out ≥0.3s, exit 불투명도는 이동 25~30% 지점에서 0, entry는 0.35에서 점화. 크로스페이드는 유지하되 "운반체 없는 경계"에만.
- `줌 스루 / 인버스 줌`(파트 타이틀 도착 전용): exit scale 1→1.2(또는 1→0.8), blur 10px(텍스트)/18~20px(풀프레임), 컷 시점 값 일치.
- 벡터 예약표: 기본 조류 = LEFT(현행 유지). 위쪽 = 파트 결론·고양. Z 후퇴 = 파트 타이틀 도착. 연속 seam 역방향 금지, 방향 전환에는 보이는 원인.
- 전환 예산: 한 편에 전환 유형 2~3종만.

**기존 수정 2건**: `.pulse` 무한 루프 → 유한 반복(청크 경계 위상 튐 방지), `go(0)` 무조건 호출 → 캡처 모드에서 첫 슬라이드 등장을 소진하지 않게.

### 3-4. 기계 게이트 확장

| 게이트 | 무엇을 막나 | 방식 |
|---|---|---|
| `check_storyboard.py` (신설) | 프레임에 route 누락, 샷 창이 구간을 안 덮음, 리빌 시각이 단어 타임스탬프 밖, 프론트로딩(첫 25%에 리빌 전부), 전환 유형 4종 이상 | STORYBOARD.md + transcript.json 대조, 결정론 |
| `check_motion.py` (신설) | "80~90% 정지 화면" 회귀 | capture.mp4 프레임 차분: 1초 격자로 변화량 측정, 정지 초 비율이 슬라이드별 임계 초과 시 경고/실패. 컷 경계 전후 4프레임의 변위 부호로 죽은 박자 근사(HF seam-gate의 번역판. 원본은 macOS+역방향 seek 전제라 이식 불가) |
| HF 감사기 주입 (신설) | 레이아웃 겹침·잘림, 명암비 | HF `check`의 브라우저 스크립트 3파일(layout/contrast/motion)은 순수 DOM이라 우리 `presentation.html`에 주입 가능(실측: 고의 파손 3종 검출, 풀링013 44점 전수). 한글 라벨 상수(ATOMIC_LABEL 16자)는 8자로 재보정 |
| 기존 유지 | 싱크 계약, 자막 안전영역 21vh, 16자 자막 | `validate_pipeline.py`·`check_caption_safe.py`·`split_captions.py` 그대로. **HF의 "캡션 밴드 폐지"는 가져오지 않는다**(HF 캡션은 4.8% 얇은 오버레이 전제, 우리는 21vh 한글 자막). 단 지속 모션 도입에 맞춰 caption-safe 샘플을 구간당 1점 → 0.5초 격자로 확대 |

### 3-5. HF 히어로 인서트 경로 (신설, 선택 연출)

- 대상: 훅 보조, 파트 타이틀, 데이터 클라이맥스, 엔딩 CTA 중 편당 0~2곳(콜라주와 합산해 오버레이 총량 ≤ 러닝타임 25% 게이트 유지).
- 방식: `04_영상소스/hf/<n>/` HF 프로젝트(핀 버전, 로컬 GSAP, Pretendard `@font-face url()`, 폴백 폰트마다 `src: local()` 스텁) → `scripts/render_hf.py`가 `npx --yes hyperframes@0.8.16 render . --output ../ov<n>.mp4 --fps 30 --quality high --workers 1` 서브프로세스 실행(Windows에서는 `npx.cmd` 명시) → `video_overlays`에 `style:"hyperframes"` 등록, `encode_overlays.py`는 건너뜀, 길이는 구간과 일치하게 루트 `data-duration` 정적 기입.
- 무음 렌더(오디오는 CapCut 트랙 소유). `lint → check(명암비 통과 팔레트) → snapshot`을 렌더 전 게이트로.
- 바로 쓸 레지스트리 부품(4색 흰 배경 호환 확인분): `count-up`, `chart-story`, `grid-card-assemble`, `state-chip-rail`, `before-after-wipe`, `marker-highlight`, `vox-annotate`, `per-word-rise`, `titlecard-lockup`, `cta-close` 등. 리포가 로컬에 있으므로 설치 = 파일 복사.
